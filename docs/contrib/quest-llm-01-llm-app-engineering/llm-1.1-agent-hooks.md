## 1. 本章目标与成果

待写。（要点：分两部分。**第一部分，钩子本身**：在 1.3 的只读钩子上加改写和中止的能力，钩子的返回值带决定（放行、改写、拒绝）；新增的位置有三个：模型调用之前（可以改写要发的对话和选项）、围着模型调用（重试和降级需要“调用下一个”的形式）、围着工具调用（权限确认、超时）；主线 1.3 已经把“调用模型”（`CallModel`）和“执行工具”（`ExecuteTool`）各放在 `src/agent.cpp` 的一个函数里，八个只读位置（`OnTurnStarted`、`OnStepStarted`、`OnReplyReceived`、`OnToolStarted`、`OnToolFinished`、`OnStepFinished`、`OnTurnFinished`、`OnError`）也在那里定好，这里不用改循环的骨架。讲清执行顺序、短路，以及钩子自己出错时怎么办（拒绝型的钩子出错，放行还是拒绝）。**第二部分，用钩子做出的能力**，按需要的主线章节排：①脱敏、预算（主线 1.4 起可做）；②重试、限流与降级：用主线 1.1 的 `Transport` 返回的错误分类决定是否重试，退避的等待用可取消的 `steady_timer`，取消时立刻结束，主 Provider 持续失败时切到备用 Provider（主线 1.2 起可做）；③权限确认与提示注入：危险工具的二次确认沿用主线 1.4 的副作用分类，确认的交互见主线 1.7，图片和用户文本里藏指令的攻击要用到主线 1.8 的视觉输入，防御用工具白名单、二次确认和输出隔离；④用量统计与提示缓存：读取响应里的用量字段，按频道统计费用，设每用户、每频道的上限，超了就拒绝（用量存进表后用 SQL 汇总，见主线 1.9；想试分析型数据库，可把同样的统计用 DuckDB 再做一遍作为练习）；历史每一轮重新生成，必须确定，同样的历史得到相同的前缀，缓存才能命中，轮次中途新消息的标记文字也要固定；每轮轨迹的 token 与费用字段和用量统计用同一批数据（轨迹见主线 2.6）。）
