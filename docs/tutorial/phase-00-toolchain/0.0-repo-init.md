## 2. 背景与概念

**为什么教程要和 Git 绑在一起。** 这份教程一步一步地从空目录长成一个完整的系统。读文字很容易，但“这一步做完时代码长什么样”只有代码本身能回答。所以每一章都对应一个 Git tag：`git checkout <tag>` 就能看到那一步完成时的全部代码，并且那个 tag 上的代码保证能编译。

**如何阅读本教程。**

| 概念 | 含义 |
|---|---|
| 章节 tag | 主线每一章一个，形如 `chapter-2.2-node-core`。章节头部写着它的 tag 和上一个 tag |
| 阶段 tag 与 Release | 主线每个阶段**开始**时打一个阶段 tag，形如 `phase-02-opencv-handles`（与阶段文件夹同名）；阶段完成后在 GitHub 上发布一个 Release |
| 选读章节 | 标题带“（选读）”，可以跳过；主线章节不依赖它们 |
| 附录 | 阶段 17–30，代码放在独立分支 `appendix/NN-<名字>` 上，**不打 tag、不发 Release**；章节头部写分支名，用 `git log <分支> --grep="^chapter-N.M"` 找到该章的提交 |
| “可开始于” | 每个附录章节会写明做完主线哪一步之后就可以开始，主线章节末尾的“可选延伸”也会列出对应的附录入口 |

**如何跟读。**

```text
git clone https://github.com/dreamldx/ComfyStudy
cd ComfyStudy
git fetch --tags
git tag -l "chapter-0.*"
git checkout chapter-0.0-repo-init
```

回到最新进度用 `git checkout main`。

**教程目录。** 教程放在 `docs/tutorial/` 下，每个阶段一个 `phase-NN-<名字>/` 文件夹，里面是该阶段的总览和各章；跨章的参考资料在 `reference/`。源码、CMakeLists.txt 等会在以后的章节里逐步出现。

## 4. 关键代码讲解

这一步没有源码，只用到了两条 Git 命令：

- `git init -b main`：在当前目录创建仓库，并把初始分支命名为 `main`。
- `git remote add origin <地址>`：给仓库登记一个名叫 `origin` 的远程地址。这一步**只是登记**，不会上传任何内容。

## 7. 技术资料

- Git 2.56.1（Windows）。主线分支固定为 `main`，主线历史保持线性。
- 设计取舍：
  - **不自动推送**：推送会把内容公开出去，所以只登记 `origin`，由维护者决定何时推送。
  - **tag 只给主线**：附录是可选的实验，放在分支里，不打 tag、不发 Release，也不合并回 `main`。
  - **被否决：教程和代码分成两个仓库。** 分开后“某一步的代码”和“某一章的文字”就要靠版本号对照，很容易错位；放在同一个仓库里，同一个提交里既有代码又有章节。
- 仓库只有一位维护者，所以 tag 在必要时可以移动并强制推送，条件是同一次改动里同步更新章节。

## 8. 常见问题与坑

- **tag 不会随普通推送一起上传。** 以后推送时要显式写：`git push origin main chapter-0.0-repo-init`，或者 `git push origin --tags`。
- **找附录的提交。** 附录没有 tag，要用 `git log appendix/18-unet-lab --grep="^chapter-18.3"` 这种方式按提交信息前缀查找。
- **改写已有 tag。** 本地移动用 `git tag -f <tag> <提交>`；已经推送过的，还要 `git push --force origin <tag>`，并且要同步更新对应章节。
