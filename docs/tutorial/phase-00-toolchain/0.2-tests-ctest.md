## 2. 背景与概念

**为什么从现在就写测试。** 这个项目后面要写很多互相配合的模块：配置解析、句柄、节点、采样器、神经网络的每一层……没有测试，改一处就不知道别处有没有坏。另外，教程每一章都要写明怎么验证这一步对不对，测试是最可靠的办法。

**测试程序长什么样。** 最简单的测试就是一个普通的 `main()`：做一些检查，全部通过就返回 0，有一项失败就返回非 0。**退出码就是测试的结果。** 这样不需要任何第三方框架。

**CTest 是什么。** CTest 是 CMake 自带的测试运行器。它做三件事：知道有哪些测试（在 `CMakeLists.txt` 里用 `add_test` 登记）、逐个运行它们、汇总结果。一个测试通过，当且仅当它的程序以退出码 0 结束。

## 4. 关键代码讲解

**测试框架 `tests/check.h`。** 只有两个宏：`CHECK(表达式)` 检查一个条件，`CHECK_EQ(a, b)` 检查两个值相等，失败时把两边的值都打印出来。它们**只记录失败，不立即停止**，这样一次运行能看到所有失败的检查。失败次数记在一个全局变量 `g_failures` 里；`inline` 让这个变量在被多个文件包含时仍然只有一份：

<!-- src: tests/check.h#L1-L27 -->
```cpp
#pragma once

#include <iostream>

// A tiny test harness: CHECK/CHECK_EQ count failures instead of stopping, and each test
// program returns a non-zero exit code when any check failed (that is what CTest looks at).
inline int g_failures = 0;

#define CHECK(expr)                                                              \
  do {                                                                           \
    if (!(expr)) {                                                               \
      ++g_failures;                                                              \
      std::cerr << __FILE__ << ':' << __LINE__ << ": CHECK failed: " #expr "\n"; \
    }                                                                            \
  } while (false)

#define CHECK_EQ(a, b)                                                         \
  do {                                                                         \
    const auto& check_left = (a);                                              \
    const auto& check_right = (b);                                             \
    if (!(check_left == check_right)) {                                        \
      ++g_failures;                                                            \
      std::cerr << __FILE__ << ':' << __LINE__ << ": CHECK_EQ failed: " #a     \
                << " == " #b "\n  left:  " << check_left                      \
                << "\n  right: " << check_right << '\n';                      \
    }                                                                          \
  } while (false)
```

几个细节：宏里的 `#expr`、`#a` 是预处理器的“字符串化”，把表达式原样变成字符串，所以失败信息里能看到你写的原话；`do { ... } while (false)` 是写多语句宏的惯用法，让宏用起来像一条普通语句；`CHECK_EQ` 先把两边各算一次存进变量，避免表达式被求值两遍。

**第一个测试 `tests/test_greeting.cpp`。** 检查 `Greeting()` 返回 `ComfyStudy ` 加版本号，并且不是空串。最后一行把失败次数变成退出码：

<!-- src: tests/test_greeting.cpp#L1-L11 -->
```cpp
#include <string>

#include "check.h"
#include "greeting.h"
#include "version.h"

int main() {
  CHECK_EQ(Greeting(), std::string("ComfyStudy ") + COMFYSTUDY_VERSION);
  CHECK(!Greeting().empty());
  return g_failures == 0 ? 0 : 1;
}
```

**登记测试 `tests/CMakeLists.txt`。** 定义一个函数 `add_comfystudy_test`：给定名字，就把 `tests/<名字>.cpp` 编译成程序，链接上一章的核心静态库，并登记给 CTest。以后每增加一个测试，只需要新建一个文件并加一行调用：

<!-- src: tests/CMakeLists.txt#L1-L9 -->
```cmake
# Builds tests/<name>.cpp into a program that links the core library and registers it
# with CTest. A test passes when the program exits with code 0.
function(add_comfystudy_test name)
  add_executable(${name} ${name}.cpp)
  target_link_libraries(${name} PRIVATE comfystudy_core)
  add_test(NAME ${name} COMMAND ${name})
endfunction()

add_comfystudy_test(test_greeting)
```

这里体现了上一章把业务代码放进静态库的好处：测试程序只需要链接 `comfystudy_core`，不需要 `main.cpp`。

**根 `CMakeLists.txt` 里的两行。** `enable_testing()` 打开 CTest 支持，**必须写在顶层** `CMakeLists.txt` 里，否则 `ctest` 会说没有找到任何测试；`add_subdirectory(tests)` 让 CMake 去读 `tests/CMakeLists.txt`：

<!-- src: CMakeLists.txt#L38-L40 -->
```cmake
# Tests: one program per tests/test_*.cpp, run with CTest.
enable_testing()
add_subdirectory(tests)
```

**测试预设。** 和配置、构建一样，测试也有预设，这样 `ctest --preset windows-debug` 就知道去哪个构建目录运行。`outputOnFailure` 让测试失败时把它的输出打印出来：

<!-- src: cmake/presets/windows.json#L36-L39 -->
```json
  "testPresets": [
    { "name": "windows-debug", "configurePreset": "windows-debug", "output": { "outputOnFailure": true } },
    { "name": "windows-release", "configurePreset": "windows-release", "output": { "outputOnFailure": true } }
  ]
```

最后，`src/version.h` 里的版本号改成了 `"0.2"`：

<!-- src: src/version.h#L1-L3 -->
```cpp
#pragma once

#define COMFYSTUDY_VERSION "0.2"
```

## 6. 验证

**一个会失败的测试什么样。** 好的测试要能真的失败。临时把测试里的期望值改成 `std::string("Wrong")`，重新构建并运行：

```text
[1/2] Building CXX object tests\CMakeFiles\test_greeting.dir\test_greeting.cpp.obj
[2/2] Linking CXX executable bin\test_greeting.exe
```

```text
ctest --preset windows-debug
```

```text
Test project <项目>/build/windows-debug
    Start 1: test_greeting
1/1 Test #1: test_greeting ....................***Failed    0.01 sec
<项目>\tests\test_greeting.cpp:8: CHECK_EQ failed: Greeting() == std::string("Wrong")
  left:  ComfyStudy 0.2
  right: Wrong


0% tests passed, 1 tests failed out of 1

Total Test time (real) =   0.01 sec

The following tests FAILED:
	  1 - test_greeting (Failed)
Errors while running CTest
```

失败信息有文件名、行号、被检查的表达式和两边的实际值。`ctest` 此时的退出码是非零（这里是 8），所以脚本和持续集成能据此判断失败。改回去再构建，测试又会通过。

**测试程序也遵守同样的依赖规则。** 上一章讲过 Ninja 靠 `/showIncludes` 记录依赖：`test_greeting.cpp` 包含了 `greeting.h`、`version.h` 和 `tests/check.h`，所以改动其中任何一个，这个测试都会被重新编译。可以用 `ninja -t deps tests/CMakeFiles/test_greeting.dir/test_greeting.cpp.obj`（在 `build\windows-debug` 目录里）确认。

## 7. 技术资料

- CTest 随 CMake 4.3.1 提供；测试预设同样需要 `CMakePresets.json` 的 `"version": 6`（CMake 3.25 及以上）。
- 常见的 C++ 测试框架：

  | 框架 | 断言写法 | 特点 |
  |---|---|---|
  | GoogleTest | `EXPECT_EQ(a, b)`（失败继续）、`ASSERT_EQ(a, b)`（失败即停） | 最普及；自带 Mock；夹具、参数化测试、`--gtest_filter` 筛选 |
  | Catch2 | `CHECK(a == b)`、`REQUIRE(a == b)` | 单一表达式写法，失败时自动展开两边的值；有 `SECTION` 与 BDD 风格 |
  | doctest | `CHECK(a == b)` | 类似 Catch2，更轻、编译更快 |
  | Boost.Test | `BOOST_CHECK_EQUAL(a, b)` | 属于 Boost，功能全，依赖较重 |

  本章的 `CHECK` / `CHECK_EQ` 是照着 Catch2、doctest 的命名写的最小版本。
- 设计取舍：
  - **本章自己写两个宏，不用测试框架。** 目的是看清测试做的事：检查条件、数失败、用退出码告诉 CTest。因为每个测试都是独立的程序，将来换框架只改测试文件本身。**从第 0.3 章起，项目改用 GoogleTest**（通过 vcpkg 引入），本章的 `tests/check.h` 会被它取代。
  - **为什么选 GoogleTest。** 它是 C++ 里使用最广的测试框架，资料最多；自带 GoogleMock，后面要模拟 LLM 的 HTTP 响应时不必再加库；Visual Studio 的 Test Explorer 能直接识别。
  - **每个测试文件一个程序。** 一个测试崩溃（比如访问越界）不会连累其他测试，退出码也各自独立。代价是链接次数多一些，对这个项目的规模可以忽略。
  - **被否决：** 在 `CMakeLists.txt` 里用 `file(GLOB ...)` 自动收集 `tests/test_*.cpp`。新增文件后 CMake 不知道要重新配置，容易“新测试没跑起来却没人发现”；显式写一行 `add_comfystudy_test(...)` 更可靠。

## 8. 常见问题与坑

- **`ctest` 说 “No tests were found!!!”。** 通常是 `enable_testing()` 没有写在顶层 `CMakeLists.txt`，或者忘了 `add_subdirectory(tests)`；也可能是还没有重新运行 `cmake --preset windows-debug`。
- **`ctest` 说找不到测试预设。** 测试预设要和配置预设配对；并且要在项目根目录运行。
- **测试通过了但其实什么也没检查。** 退出码为 0 就算通过，所以一个 `main` 里一个 `CHECK` 都没写的测试永远通过。养成习惯：新测试先让它失败一次（像上面的“Wrong”实验），确认它真的在检查东西。
- **失败时看不到输出。** 没有打开 `outputOnFailure`（我们的预设已经打开了）；也可以临时用 `ctest --preset windows-debug -V` 看每个测试的完整输出。
- **`CHECK_EQ` 的两边类型不能打印。** `CHECK_EQ` 用 `std::cerr <<` 打印两边的值，所以类型必须支持 `<<`（字符串、整数没问题）；自定义类型要先为它写 `operator<<`。
