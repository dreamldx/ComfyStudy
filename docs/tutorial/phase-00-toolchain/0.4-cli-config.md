## 1. 本章目标与成果

项目后面要连 Discord、调用 LLM 接口，需要 Discord Token、API 密钥、模型名、模型目录这类配置。这一章做读取配置的部分：

- 用上一章装好的 **CLI11** 解析命令行，**同时**读取配置文件（`config.toml` 或 `config.ini`，两种语法都认）。
- 同一个设置有三个来源，**优先级从低到高**是：环境变量 < 配置文件 < 命令行。没有任何来源时，用内置的默认值。
- 一个**配置模块**（`config`）：列出项目认识的 9 个设置，显示时**把密钥打码**。
- 主程序支持 `--config <路径>`、`-v/--verbose`，以及每个设置对应的命令行选项（如 `--llm_model`）；没有 `--config` 时，按固定顺序自己找配置文件；`--help` 自动列出所有选项。
- 加载过程用上一章引入的 **spdlog** 记录日志。
- 两个配置模板 `config.toml.example` 和 `config.ini.example`，真正的 `config.toml`、`config.ini` 不会提交进 Git。

## 2. 背景与概念

**为什么要有配置文件。** 密钥不能写进代码，也不能提交进 Git，一旦提交，即使以后删掉，历史里也还在。常见做法是把配置放进环境变量，程序启动时读取。但本地开发时，每次开终端都设一遍环境变量很麻烦，所以再加一个配置文件：只存在于你自己的机器上，仓库里只提交没有真实值的模板。临时想换一个值（比如试另一个模型），又不想改文件，就直接写在命令行上。

**三个来源，一条优先级。** 同一个设置，可能同时出现在几个地方。我们规定，后面的盖过前面的：

| 来源 | 例子（设置 `llm_model`） | 优先级 |
|---|---|---|
| 内置默认值 | `llm_provider` 默认 `openai` | 最低 |
| 环境变量 | `set LLM_MODEL=gpt-4o` | ↑ |
| 配置文件 | `llm_model = "gpt-4o-mini"` | ↑ |
| 命令行 | `--llm_model gpt-4o-mini` | 最高 |

道理很实在：环境变量是“这台机器、这个终端”的背景设置；配置文件是“这个项目”专门写下的意图，要比背景更具体；命令行是“这一次运行”的临时指定，最具体。

**同一个名字走到底。** 一个设置在三个地方用的名字几乎一样，不用记对照表：

| 设置 | 配置文件里 | 命令行 | 环境变量 |
|---|---|---|---|
| 模型名 | `llm_model` | `--llm_model` | `LLM_MODEL` |
| OpenAI 密钥 | `openai_api_key` | `--openai_api_key` | `OPENAI_API_KEY` |
| 模型目录 | `model_dir` | `--model_dir` | `MODEL_DIR` |

配置文件和命令行用同一个小写加下划线的名字；环境变量是这个名字的大写。**配置文件里不分节**，就是一行一个 `名字 = 值`。

**CLI11 的基本用法。** 先建一个 `CLI::App`，再用 `add_option("--名字", 变量)` 声明有哪些选项，最后 `parse`。CLI11 负责：把字符串转成变量的类型、检查缺少值或不认识的选项、生成 `--help`。读配置文件靠 `set_config("--config", 默认文件, 说明)`：它加了一个 `--config <文件>` 选项，解析时顺便读这个文件，**文件里的名字按选项名匹配**（所以配置文件的键就是 `llm_model`，和 `--llm_model` 同名）。CLI11 保证：**同一个选项，命令行给了值，就不再用配置文件里的**，所以“配置文件 < 命令行”它帮我们做了。

**INI 和 TOML。** 两种都是“键 = 值”的文本配置格式。INI 很老、很宽松：值可以不加引号，`;` 或 `#` 开头是注释。TOML 更新、更严格：字符串要加引号，只有 `#` 是注释。CLI11 的默认读取器两种写法**都认**，我们不用区分：

| 写法 | 怎么读 |
|---|---|
| `llm_model = gpt-4o`（INI） | 值是 `gpt-4o` |
| `llm_model = "gpt-4o"` 或 `'gpt-4o'`（TOML） | 引号去掉，值是 `gpt-4o` |
| `llm_model = "a b c"` | 带空格的值**必须加引号**；不加引号 `a b c` 会被当成三个值，最后只留下 `c` |
| `# 注释`、`; 注释` | 整行是注释；`llm_model = a # note` 行尾的 `#` 也是注释，值是 `a` |
| `llm_model = "a # b"` | 引号里的 `#` 不是注释 |
| 空值 `llm_model =` 或 `llm_model = ""` | **视为没有设置**（见下面“空值”） |
| 同一个名字写了两次 | 后面的生效 |
| 名字写错、大小写不对（`LLM_MODEL`）、没有 `=` 的行 | **报错**，指出哪个名字不认识 |
| `[节]` | 不支持，会报错（CLI11 把节当成子命令，我们没有） |
| UTF-8 BOM、`\r\n` 换行 | BOM 由我们去掉，`\r\n` CLI11 能处理 |

报错而不是悄悄忽略，是因为配置里写错名字几乎总是手误；悄悄忽略的话，你会以为配置生效了。CLI11 的报错文字写的是 “INI was not able to parse ……”，即使文件是 TOML 也这么写。

**空值：不覆盖，只当没写。** 模板里密钥那几行是留空的（`discord_token = ""`）。如果你把 token 放在环境变量里，又原样复制了模板，按“配置文件优先”，空字符串会盖掉环境变量里的真值，这太反直觉。所以我们规定：**在任何一级，空值都等于没有设置**。命令行、配置文件的值是空时，继续往下一级找（环境变量，再是默认值）。

**怎么找配置文件。**

1. 命令行给了 `--config <路径>`：只用这个文件。文件不存在就报错退出（你明确要求的，不能悄悄忽略）。
2. 没给：依次试可执行文件所在目录、再试当前工作目录；每个目录里先试 `config.toml`，再试 `config.ini`。用第一个存在的，**不合并**。
3. 都没有：提示一句，只用环境变量和默认值，正常运行。

开发时让程序读到项目根目录的配置文件：先进入项目根目录，再运行程序（这时当前工作目录就是项目根）：

```text
cd <项目根>
build\windows-debug\bin\comfystudy.exe
```

**日志。** 程序运行时发生的事（读了哪个文件、没找到配置文件）用 spdlog 记录：`info` 是正常信息，`warn` 是需要注意但能继续的情况，`debug` 是更详细的过程，默认只显示 `info` 及以上，加 `-v` 或 `--verbose` 才显示 `debug`。格式是 `[级别] 消息`。程序的**正常输出**（问候、libcurl 版本、配置列表）仍然用 `std::cout`，日志只用来说明过程。配置本身出错（找不到指定的文件、写错名字）是 CLI11 直接打印错误并退出，退出码非零。

**密钥遮蔽。** 程序会打印配置，方便确认读对了，但**密钥绝不能原样出现在输出里**（终端记录、日志、截图都可能泄露）。名字以 `_key` 或 `_token` 结尾的算密钥：空值显示 `(unset)`，短于 8 个字符显示 `****`，否则只显示前 3 个字符加 `***`。短密钥完全不显示，是因为显示三个字符就泄露了一大半。

**命令行里的密钥要小心。** 命令行参数别人是看得到的：在任务管理器、`Get-Process` 里能看到进程的完整命令行，终端的历史记录里也会留下。**平时把密钥放在配置文件或环境变量里**，命令行适合放模型名、目录这类不敏感的临时指定。上面的 `--openai_api_key` 选项只是为了让“三个来源”统一，不建议这样传密钥。

## 4. 关键代码讲解

**设置的列表。** 每个设置是一个 `Key`：名字（配置文件和命令行用）、环境变量名、默认值、是不是密钥。`Values` 是解析后的结果：名字到值的表，空字符串表示没有设置：

<!-- src: src/config.h#L13-L26 -->
```cpp
// One setting. `name` is how it is written in a config file ("llm_model = ...") and on the command
// line ("--llm_model"); `env` is the environment variable that can also provide it.
struct Key {
  std::string name;
  std::string env;
  std::string default_value;  // used when nothing else provides a value; empty means "no default"
  bool secret;                // true when the name ends with "_key" or "_token"
};

// The settings ComfyStudy knows about, in a fixed order.
const std::vector<Key>& KnownKeys();

// Resolved settings: one entry per known key, keyed by Key::name; an empty string means "not set".
using Values = std::map<std::string, std::string>;
```

列表在 `config.cpp` 里。环境变量名不用手写，由名字转成大写得到（`EnvName`）；是不是密钥由名字的后缀判断，所以以后新加一个 `xxx_api_key`，会自动被遮蔽，不会因为忘了登记而泄露：

<!-- src: src/config.cpp#L32-L51 -->
```cpp
const std::vector<Key>& KnownKeys() {
  static const std::vector<Key> keys = [] {
    const std::pair<const char*, const char*> settings[] = {
        {"discord_token", ""},
        {"llm_provider", "openai"},
        {"llm_model", ""},
        {"openai_api_key", ""},
        {"openai_base_url", "https://api.openai.com/v1"},
        {"anthropic_api_key", ""},
        {"anthropic_base_url", "https://api.anthropic.com"},
        {"model_dir", "models"},
    };
    std::vector<Key> out;
    for (const auto& [name, default_value] : settings) {
      out.push_back({name, EnvName(name), default_value, IsSecretName(name)});
    }
    return out;
  }();
  return keys;
}
```

**读取环境变量与遮蔽。** 读环境变量用 `_dupenv_s`，它把值**复制**一份（用完要 `free`）。不用 `getenv`，因为 MSVC 认为它不安全，会报弃用警告，而我们开着 `/WX`，警告就是错误。空的环境变量当作没有设置。读环境变量和下面取程序目录都是 Windows 专属的代码，所以用 `#if defined(_WIN32)` 包起来；别的系统走 `#else` 分支，那里是一句明确的 `#error`，在别的系统上编译时会立刻停下并说明缺什么。`Describe` 输出 `名字=值`：没设置显示 `(unset)`，密钥显示遮蔽后的值：

<!-- src: src/config.cpp#L53-L81 -->
```cpp
std::optional<std::string> Get(std::string_view env_name) {
  std::string value;
#if defined(_WIN32)
  char* buffer = nullptr;
  std::size_t length = 0;
  if (_dupenv_s(&buffer, &length, std::string(env_name).c_str()) != 0 || buffer == nullptr) {
    return std::nullopt;
  }
  value = buffer;
  free(buffer);
#else
#error "config::Get is not implemented for this platform on this branch"
#endif
  if (value.empty()) return std::nullopt;
  return value;
}

std::string MaskSecret(std::string_view value) {
  if (value.empty()) return "(unset)";
  if (value.size() < 8) return "****";
  return std::string(value.substr(0, 3)) + "***";
}

std::string Describe(const Values& values, const Key& key) {
  std::string line = key.name + '=';
  const auto found = values.find(key.name);
  if (found == values.end() || found->second.empty()) return line + "(unset)";
  return line + (key.secret ? MaskSecret(found->second) : found->second);
}
```

**可执行文件所在目录与搜索顺序。** 用 Windows 的 `GetModuleFileNameW` 取当前程序的完整路径。**不能用 `argv[0]`**：它只是启动时命令行里的第一个词，可能只是个相对的名字，甚至没有路径。缓冲区先给 `MAX_PATH`，装不下就翻倍重试。`ConfigCandidates` 是个纯函数，只返回候选路径的列表，所以不用碰文件系统就能测试它的顺序：

<!-- src: src/config.cpp#L87-L108 -->
```cpp
std::filesystem::path ExeDirectory() {
#if defined(_WIN32)
  std::wstring buffer(MAX_PATH, L'\0');
  for (;;) {
    const DWORD copied = GetModuleFileNameW(nullptr, buffer.data(), static_cast<DWORD>(buffer.size()));
    if (copied == 0) return {};
    if (copied < buffer.size()) {
      buffer.resize(copied);
      break;
    }
    buffer.resize(buffer.size() * 2);  // the path did not fit: try a bigger buffer
  }
  return std::filesystem::path(buffer).parent_path();
#else
#error "config::ExeDirectory is not implemented for this platform on this branch"
#endif
}

std::vector<std::filesystem::path> ConfigCandidates(const std::filesystem::path& exe_dir,
                                                    const std::filesystem::path& cwd) {
  return {exe_dir / "config.toml", exe_dir / "config.ini", cwd / "config.toml", cwd / "config.ini"};
}
```

**对外的接口。** `options.h` 里没有任何 CLI11 的东西。`Parse` 收到命令行参数和候选配置文件，返回解析好的设置、`verbose` 标志、读的是哪个配置文件，以及“是否应该立刻退出”（`--help` 或参数出错时）：

<!-- src: src/options.h#L1-L39 -->
```cpp
#pragma once

#include <filesystem>
#include <optional>
#include <ostream>
#include <string>
#include <vector>

#include "config.h"

namespace options {

struct Options {
  config::Values values;                          // every known key, resolved (see Parse)
  bool verbose = false;                           // -v / --verbose
  std::optional<std::filesystem::path> config_file;  // the config file that was read, if any
};

struct Result {
  Options options;
  // Set when the program should stop right away: --help (0) or a bad command line or config
  // file (non-zero). The usage or the error message has already been written to out / err.
  std::optional<int> exit_code;
};

// Resolves every known setting from, in increasing priority:
//   built-in default  <  environment variable  <  config file  <  command line
// An empty value counts as "not set" at every level, so an empty `token =` in a config file does
// not hide a token that comes from the environment.
//
// `args` are the command-line arguments after the program name. The config file is the one given
// with --config; without it, the first existing file in `config_candidates` (no merging). It may
// be written as INI or as TOML (a flat list of "name = value" lines). A setting has the same
// name in the file and on the command line: "llm_model = x" is "--llm_model x".
Result Parse(const std::vector<std::string>& args,
             const std::vector<std::filesystem::path>& config_candidates, std::ostream& out,
             std::ostream& err);

}  // namespace options
```

**配置文件读取器。** CLI11 自带的读取器已经认 INI 和 TOML。我们只多做一件事：去掉文件开头的 UTF-8 BOM。有些 Windows 编辑器保存时会加这三个字节，CLI11 不认，会把它当成第一个名字的一部分，于是第一个设置悄悄“丢了”，或者报“不认识的名字”。做法是继承 `CLI::ConfigBase`，重写 `from_config`，先把整个文件读成字符串、去掉 BOM，再交给基类：

<!-- src: src/options.cpp#L12-L34 -->
```cpp
constexpr std::string_view kBom = "\xEF\xBB\xBF";

// CLI11 reads a UTF-8 BOM (which some Windows editors put at the start of a file) as part of the
// first name, so "discord_token" would not be recognized. This reader drops it first. The base
// class understands both INI and TOML syntax: '#' and ';' comments, "name = value", and values
// that are quoted or not.
class ConfigReader : public CLI::ConfigBase {
 public:
  std::vector<CLI::ConfigItem> from_config(std::istream& input) const override {
    std::string text((std::istreambuf_iterator<char>(input)), std::istreambuf_iterator<char>());
    if (text.compare(0, kBom.size(), kBom) == 0) text.erase(0, kBom.size());
    std::istringstream stream(text);
    return CLI::ConfigBase::from_config(stream);
  }
};

std::string DefaultConfigFile(const std::vector<std::filesystem::path>& candidates) {
  for (const auto& candidate : candidates) {
    std::error_code ignored;
    if (std::filesystem::is_regular_file(candidate, ignored)) return candidate.string();
  }
  return {};
}
```

文件旁边的 `DefaultConfigFile` 在候选路径里找第一个存在的文件，没有就返回空字符串。

**解析：声明选项，再决定优先级。** 先为每个设置声明一个选项，名字是 `--` 加设置名，说明文字里写上对应的环境变量；`multi_option_policy(TakeLast)` 让同一个名字出现多次时留最后一个。`set_config` 加上 `--config`，默认值就是找到的候选文件（没找到是空字符串，表示没有默认文件）。`allow_config_extras(error)` 让配置文件里不认识的名字变成错误。

`parse` 之后，命令行和配置文件已经按“命令行优先”应用好了。剩下的空值依次用环境变量、内置默认值补上，这就完成了“默认值 < 环境变量 < 配置文件 < 命令行”。出错或者 `--help` 时，CLI11 抛出 `CLI::ParseError`，`app.exit(e, out, err)` 把帮助或错误信息写到我们给的流里，并返回退出码，我们记下退出码，由 `main` 决定退出：

<!-- src: src/options.cpp#L38-L73 -->
```cpp
Result Parse(const std::vector<std::string>& args,
             const std::vector<std::filesystem::path>& config_candidates, std::ostream& out,
             std::ostream& err) {
  Result result;
  CLI::App app{"ComfyStudy: an LLM-driven image generation bot", "comfystudy"};

  for (const config::Key& key : config::KnownKeys()) {
    app.add_option("--" + key.name, result.options.values[key.name],
                   "Environment variable: " + key.env)
        ->multi_option_policy(CLI::MultiOptionPolicy::TakeLast);  // a repeated key: last wins
  }
  app.add_flag("-v,--verbose", result.options.verbose, "Show debug messages");

  CLI::Option* config_option = app.set_config(
      "--config", DefaultConfigFile(config_candidates), "Read settings from this INI or TOML file");
  app.config_formatter(std::make_shared<ConfigReader>());
  app.allow_config_extras(CLI::config_extras_mode::error);  // a misspelled key is an error

  try {
    std::vector<std::string> reversed(args.rbegin(), args.rend());  // CLI11 wants them reversed
    app.parse(reversed);
  } catch (const CLI::ParseError& e) {
    result.exit_code = app.exit(e, out, err);
    return result;
  }

  if (config_option->count() > 0) result.options.config_file = config_option->as<std::string>();

  // The command line and the config file are already applied (CLI11 gives the command line
  // priority). What is still empty falls back to the environment, then to the built-in default.
  for (const config::Key& key : config::KnownKeys()) {
    std::string& value = result.options.values[key.name];
    if (value.empty()) value = config::Get(key.env).value_or(key.default_value);
  }
  return result;
}
```

注意 `parse` 要的是**倒过来**的参数列表（上一章说过），所以先反转。`config_option->count() > 0` 表示确实读了一个配置文件，`as<std::string>()` 取出它的路径。

**主程序。** 先解析（解析失败或 `--help` 就按退出码结束，这时 CLI11 已经打印了信息），再设置日志格式和级别，打印问候和版本，记录读了哪个配置文件，最后打印遮蔽后的配置：

<!-- src: src/main.cpp#L12-L44 -->
```cpp

int main(int argc, char** argv) {
  // Flush std::cout after every output, so its lines and spdlog's lines (which are written
  // immediately) stay in the order the program produced them even when stdout is redirected.
  std::cout << std::unitbuf;

  const std::vector<std::string> args(argv + 1, argv + argc);
  const auto candidates =
      config::ConfigCandidates(config::ExeDirectory(), std::filesystem::current_path());
  const options::Result parsed = options::Parse(args, candidates, std::cout, std::cerr);
  if (parsed.exit_code) return *parsed.exit_code;  // --help, or a bad command line or config file

  spdlog::set_pattern("[%l] %v");
  if (parsed.options.verbose) spdlog::set_level(spdlog::level::debug);

  std::cout << Greeting() << '\n';
  std::cout << CurlVersion() << '\n';

  for (const auto& candidate : candidates) {
    spdlog::debug("config candidate {}: {}", candidate.string(),
                  std::filesystem::exists(candidate) ? "found" : "not found");
  }
  if (parsed.options.config_file) {
    spdlog::info("loaded {}", parsed.options.config_file->string());
  } else {
    spdlog::warn(
        "no config file found (looked next to the executable and in the current directory); "
        "using the environment and the defaults only");
  }

  config::Print(std::cout, parsed.options.values);
  return 0;
}
```

`std::cout << std::unitbuf` 让 `std::cout` 每输出一次就立刻刷新。原因是 spdlog 写日志是立即输出的，而 `std::cout` 在输出被重定向到文件或管道时是攒着输出、最后才一起写：不加这一行，重定向之后日志会跑到问候语的前面，顺序就乱了。

```cpp
class OptionsTest : public testing::Test {
 protected:
  void SetUp() override {
    for (const config::Key& key : config::KnownKeys()) {
      saved_.emplace_back(key.env, config::Get(key.env));
      _putenv_s(key.env.c_str(), "");
    }
  }
  void TearDown() override {
    for (const auto& [name, value] : saved_) _putenv_s(name.c_str(), value.value_or("").c_str());
  }

  static void SetEnv(const char* name, const char* value) { _putenv_s(name, value); }

  // Runs Parse with no config-file candidates; the output goes to out_ and err_.
  options::Result Run(const std::vector<std::string>& args,
                      const std::vector<std::filesystem::path>& candidates = {}) {
    return options::Parse(args, candidates, out_, err_);
  }

  std::ostringstream out_;
  std::ostringstream err_;

 private:
  std::vector<std::pair<std::string, std::optional<std::string>>> saved_;
};
```

## 7. 技术资料

- CLI11 2.7.2（上一章用 vcpkg 装好）。用到的接口：`CLI::App`、`add_option`、`add_flag`、`set_config`、`config_formatter`、`allow_config_extras`、`multi_option_policy`、`app.exit`、`CLI::ParseError`、`CLI::ConfigBase`（读取器的基类）。文档：CLI11 手册里的 “Config files” 一节。
- 日志库 spdlog（上上一章引入）。用到的接口：`spdlog::info/warn/debug`（`{}` 格式化）、`spdlog::set_level`、`spdlog::set_pattern`。默认日志器写到标准输出。
- 用到的 Windows / C 运行库函数：`_dupenv_s`（读取并复制一份环境变量，用完要 `free`）、`GetModuleFileNameW`（取当前可执行文件的完整路径）。
- 设计取舍：
  - **用 CLI11，不自己写命令行循环和解析器。** 命令行、配置文件的读取、错误提示、`--help` 都是现成的，我们只描述“有哪些设置”。代价是多依赖一个库，并且要接受它的一些约定（`--名字` 和配置键同名、错误信息的措辞）。
  - **配置文件不分节，键和选项同名。** CLI11 把 `[节]` 当成子命令，用节来分组需要给读取器加一层转换。我们的设置不多，平铺更简单，也让命令行、配置文件、环境变量的名字一一对应。
  - **INI 和 TOML 都支持，靠同一个读取器。** 两种语法在“键 = 值”这个范围内基本重合，一个读取器全部接住；代价是不能用 TOML 的类型（数字、数组、表）和严格校验，我们所有的值都是字符串。
  - **优先级：默认值 < 环境变量 < 配置文件 < 命令行。** 命令行优先于配置文件由 CLI11 保证；环境变量和默认值我们在 `parse` 之后补。CLI11 自己的 `envname` 也是“命令行 > 配置文件 > 环境变量”的顺序，但配置文件里的空值（`token =`）会被它当成“已经设置”，从而盖掉环境变量；我们要的是空值等于没写，所以自己补。
  - **空值等于没有设置。** 让模板里留空的密钥不会盖掉环境变量；代价是没办法用“空字符串”故意清掉一个设置。
  - **写错名字是错误，不是警告。** `allow_config_extras(error)`；代价是以后配置文件里留一个暂时没用的键也会报错。
  - **配置文件和环境变量里的密钥不记入日志，命令行里的密钥不建议使用。** 打印时一律遮蔽，并有测试保证解析过程不输出密钥的值。
  - **日志与正常输出分开。** 问候、版本和配置列表是程序的输出，用 `std::cout`；读了哪个文件这类过程信息是日志，用 spdlog。这样以后把输出接给别的程序时，日志不会混进数据里。
  - **第一个存在的文件生效，不合并。** 行为好预测，也不会出现“这个值到底来自哪个文件”的疑问。同一目录 `config.toml` 排在 `config.ini` 前面。
  - **被否决：** 在 `parse` 之前预先扫描命令行找 `--config`（要自己写一遍参数解析，和 CLI11 重复）；构建时把配置文件复制到可执行文件旁边（多一个构建步骤，改了配置还要重新构建）；把源码目录的绝对路径编译进程序（二进制里带着你机器上的路径）；从可执行文件目录往上逐级找（可能找到别的项目的配置文件，对密钥文件很危险）；用 `std::regex` 自己解析配置文件（规则不适合一条正则，MSVC 的实现还有性能和栈深度问题）。
- 环境变量只影响当前进程和它启动的子进程，进程结束就消失；我们现在不再把配置文件的内容写进环境变量，所有设置都通过 `Values` 传递。

## 8. 常见问题与坑

- **运行了程序却读不到配置文件。** 先看输出的 `[info] loaded ...` 或 `[warning] no config file found`，加 `-v` 能看到它找了哪四个位置。最常见的原因是**不在项目根目录运行**：当前目录里没有配置文件，可执行文件旁边也没有。进入项目根目录再运行，或者用 `--config <路径>`。
- **从别的目录运行却读到了别处的配置文件。** 规则就是读当前目录的，如果你在一个放着别的 `config.toml` 的目录里运行，会读到那一个。看输出里的 `loaded` 路径可以确认读的是哪一个。
- **报 `INI was not able to parse xxx`。** 文件里有一个名字不认识：拼错了（`llm_modle`）、大小写不对（名字全是小写）、写了 `[节]`、或者有一行没有 `=`。把名字改成 `--help` 里列出的那些。
- **值被截断，只剩最后一个词。** 值里有空格但没加引号，`llm_model = a b c` 被当成三个值，只留了最后的 `c`。给值加引号：`llm_model = "a b c"`。
- **值里需要 `#`。** 不加引号时，行内的 `#` 是注释的开始；用引号把整个值包起来（`"a # b"`），引号里的 `#` 就是普通字符。
- **配置里写了值，输出却是 `(unset)`。** 空值被当成没设置；检查是不是写成了 `llm_model = ""`，或者写错了位置（写在注释里）。
- **环境变量设了，配置文件里同名的设置却盖住了它。** 这是规则：配置文件优先于环境变量。要让环境变量生效，把配置文件里的那一行删掉或注释掉，或者留空。
- **第一个设置总是读不到，或者密钥总是认证失败。** 多半是文件带了 BOM 或 `\r\n`。本章的代码已经处理了；自己写别的读取逻辑时，要记得这两点。
- **`config.toml` 或 `config.ini` 被提交进了 Git。** 它含有真实的密钥，一旦提交，即使以后删除，历史里也还在。如果误提交了，要先在对应的服务里**作废并重新生成**那个密钥，再处理仓库。本项目已经设置成不提交，只提交 `.example` 模板。
- **输出被重定向后，日志跑到了问候语前面。** `std::cout` 重定向后是攒着输出的，而 spdlog 立即写。`main` 里加了 `std::cout << std::unitbuf;` 让两者保持程序产生的顺序；自己写别的程序时要留意这一点。
- **想看更详细的过程却什么也没多出来。** 要加 `-v` 或 `--verbose`，`debug` 级别默认是关的。
- **在输出或日志里贴了完整的密钥。** 用 `config::Describe` 或 `config::Print` 输出配置，不要自己拼字符串打印设置的值；写日志时也只写名字。
- **`parse` 的参数顺序不对。** 给 `parse(std::vector<std::string>)` 的列表要倒过来（最后一个参数在最前面），忘了反转的话，选项和它的值会被拆开。
