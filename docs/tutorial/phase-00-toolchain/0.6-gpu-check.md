# 0.6 检测 GPU 与 CUDA 驱动

- 状态：已打 tag ｜ 类型：主线 ｜ tag：`chapter-0.6-gpu-check` ｜ 上一 tag：`chapter-0.5-dll-management`
- 所属阶段：[阶段 0：工具链与骨架](README.md)
- 一句话目标：在项目里默认检测 GPU 能不能用：写一个只依赖 NVIDIA 驱动的探针 `gpu_probe`（不要 `nvcc`，不要 `cuda.h`，Windows 与 Linux 同一份源码），它作为 CTest 测试随项目运行，并给 `check-env.ps1` 加 `-Gpu`

## 1. 本章目标与成果

后面的阶段要在 GPU 上跑 libtorch 和 ggml。动手之前，先确认一件很具体的事：这台机器上，一个普通的程序能不能用上显卡？`nvidia-smi` 能打印出显卡的名字，只说明驱动装了；程序要用，还得能加载驱动、初始化、建出上下文。这一章写一个很小的探针程序做这件事，并把它接进项目的测试和环境检查。做完后你会得到：

- **`tools/gpu-probe`：一个只依赖驱动的探针。** 它调用 NVIDIA 驱动自带的库：初始化、读驱动支持的 CUDA 版本、找到第一块显卡、读计算能力、创建并释放主上下文。它不用 `nvcc`，也不用 `cuda.h`，用到的几个函数在源码里自己声明。
- **一个默认就会运行的测试 `gpu_probe`。** 主项目的 `CMakeLists.txt` 无条件加入这个目录，没有开关。有显卡的机器上，`ctest` 会真的在 GPU 上跑一遍；没有驱动库就显示为 Disabled，没有设备就显示为 Skipped，都不算失败。
- **`check-env.ps1 -Gpu`：** 在原来的工具检查之后，再检查 `nvidia-smi`，并单独配置、构建、运行探针。它不拉项目的 vcpkg 依赖，所以在项目还不能配置的时候也能用。
- **同一份源码，两个平台。** Windows 链接 `cuda.lib`，Linux 链接 `libcuda.so`，探针的源码一行不改。Linux 支线 [platform-1.5](../../contrib/quest-platform-01-linux-foundation/platform-1.5-cuda-env.md) 在同一个探针上加 `check-env.sh --gpu`。
- **一个值得记下来的现象：** 这台机器上的 CUDA 工具包是 13.5，而驱动只支持到 13.4。探针把驱动那个数字读出来；它不替你判断这是不是问题。

先看效果。在 MSVC 环境里运行（`scripts\dev.ps1` 已经配好）：

```text
scripts\dev.ps1 powershell -NoProfile -File scripts\check-env.ps1 -Gpu
```

```text
（前面 8 行是 cl、link、dumpbin、cmake、ninja、git、vcpkg、powershell，和以前一样）
OK      nvidia-smi: NVIDIA GeForce RTX 4090, 616.56, supports CUDA 13.4
OK      gpu: NVIDIA GeForce RTX 4090 (compute capability 8.9), context created
check-env: OK
```

`nvidia-smi` 那一行告诉你显卡、驱动版本（616.56）和驱动支持的 CUDA 版本（13.4）。`gpu` 那一行是探针的结果：它真的在这块显卡上建出了上下文。不带 `-Gpu` 时，输出和上一章完全一样。

## 2. 背景与概念

**驱动和工具包是两回事。** 装 NVIDIA 驱动，得到的是内核模块和一批用户态的库，其中有 `nvcuda.dll`（Windows）或 `libcuda.so`（Linux），这是 CUDA 的 **Driver API**。再往上，CUDA 工具包带来 `nvcc` 编译器、头文件、运行时库 `cudart`、`cublas` 等。程序用的 CUDA 最终都要经过驱动，所以“能不能用 GPU”首先取决于驱动，而不是工具包。本章只检查驱动这一层。后面的章节用到 `nvcc` 或 cuDNN 时，再检查它们。

**为什么不直接用 `nvidia-smi`。** `nvidia-smi` 通过 NVML 读取显卡的状态，能告诉你驱动在、显卡在。但它不会替你创建 CUDA 上下文：显卡被别的进程独占、驱动版本太旧、容器里没有透传设备，这些情况下 `nvidia-smi` 可能仍然能打印出东西，而程序一初始化就失败。所以探针要像一个程序那样去调用驱动。

**版本号的两个数字。** 驱动报告的是它支持的 **CUDA 版本**，`13040` 表示 13.4（主版本乘 1000，加次版本乘 10）。工具包有自己的版本，比如 13.5。CUDA 13.x 允许“工具包比驱动新”，只要驱动不低于 13.0（对应驱动分支 R580 以上）；具体用到的功能是否可用，要看那个功能自己的要求。所以探针只设一个下限：驱动支持的 CUDA 版本不低于 13.0。这个下限只写在 `probe.cpp` 里，脚本不重复。

**主上下文。** CUDA 上下文是一个进程使用某块 GPU 的状态。CUDA 运行时和 cuDNN、cuBLAS 这些库用的是每块显卡的**主上下文**（primary context）。探针保留再释放主上下文，创建成功就说明运行时库以后也能在这块卡上工作。

**为什么自己声明函数，不用 `cuda.h`。** `cuda.h` 在工具包里。Linux 机器可能只有驱动，没有工具包，这时没有这个头文件。探针只用 Driver API 里八个稳定的函数，把原型写在源码里，两边都能编译。代价是原型必须和驱动的实际接口一致，写错了编译器和链接器不一定能发现，所以只选几个稳定的函数，并在 Windows 和 Linux 上都真的运行一遍。

**两个坑。** 一是 `cuda.h` 里很多函数名带版本后缀，头文件用宏把不带后缀的名字改成当前版本，比如 `cuDevicePrimaryCtxRelease` 实际是 `cuDevicePrimaryCtxRelease_v2`。没有头文件时，要自己写后缀；不带后缀的旧名字还能链接上，但接口是旧的。我用 `nm -D`（Linux）看过 `libcuda.so` 的导出符号，确认 `_v2` 存在。二是 Windows 上 `cuda.lib` 是工具包带的导入库，没装工具包的 Windows 机器上，`find_library` 找不到它，测试就显示为 Disabled。

**为什么放进主项目，而且没有开关。** 这样每次构建和测试都会检查 GPU，不用记得去运行额外的命令。没有显卡的机器怎么办？找不到库时，CMake 配置只打印一行 `-- GPU: ...`，不失败，测试登记为 Disabled；找到库但没有设备，探针退出码 77，CTest 把它当作 Skipped。驱动在但版本太低，或者哪一步调用出错，探针退出码 1，是真正的失败。

## 4. 关键代码讲解

**探针的接口。** 先声明要用的函数。`extern "C"` 保证名字不被 C++ 改写；`CUresult` 和 `CUdevice` 都是 `int`，`CUcontext` 是不透明指针。

<!-- src: tools/gpu-probe/probe.cpp#L9-L26 -->
```cpp
#include <cstdio>

extern "C" {
using CUresult = int;
using CUdevice = int;
struct CUctx_st;
using CUcontext = CUctx_st*;

CUresult cuInit(unsigned int flags);
CUresult cuDriverGetVersion(int* version);
CUresult cuDeviceGetCount(int* count);
CUresult cuDeviceGet(CUdevice* device, int ordinal);
CUresult cuDeviceGetName(char* name, int length, CUdevice device);
CUresult cuDeviceGetAttribute(int* value, int attribute, CUdevice device);
CUresult cuDevicePrimaryCtxRetain(CUcontext* context, CUdevice device);
// The "_v2" name is the current one; the plain name is the old interface that cuda.h hides.
CUresult cuDevicePrimaryCtxRelease_v2(CUdevice device);
}
```

**退出码和版本下限。** 三个退出码在源码最前面写明。`kNoDevice` 是 `cuInit` 在没有设备时返回的 `CUDA_ERROR_NO_DEVICE`。`kMinDriverCuda` 是驱动支持的 CUDA 版本的下限，写成 `13000`，也就是 13.0。

<!-- src: tools/gpu-probe/probe.cpp#L28-L48 -->
```cpp
namespace {

constexpr int kExitOk = 0;
constexpr int kExitBroken = 1;
constexpr int kExitSkip = 77;

constexpr CUresult kSuccess = 0;
constexpr CUresult kNoDevice = 100;  // CUDA_ERROR_NO_DEVICE
constexpr int kAttrComputeMajor = 75;  // CU_DEVICE_ATTRIBUTE_COMPUTE_CAPABILITY_MAJOR
constexpr int kAttrComputeMinor = 76;  // CU_DEVICE_ATTRIBUTE_COMPUTE_CAPABILITY_MINOR

// The oldest driver we accept: CUDA 13.0 (the version number is major * 1000 + minor * 10).
// Programs built with a CUDA 13 toolkit need a driver that supports 13.x.
constexpr int kMinDriverCuda = 13000;

int Fail(const char* step, CUresult result) {
  std::printf("error: %s returned %d\n", step, result);
  return kExitBroken;
}

}  // namespace
```

**调用的顺序。** `main` 按顺序走：初始化，读版本，数设备，读名字和计算能力，保留并释放主上下文。每一步失败都打印步骤名和 `CUresult` 的数字，再退出。`cuInit` 返回“没有设备”和数量为 0 是“没有东西可测”，退出 77。

<!-- src: tools/gpu-probe/probe.cpp#L50-L101 -->
```cpp
int main() {
  CUresult r = cuInit(0);
  if (r == kNoDevice) {
    std::printf("skip: the driver reports no CUDA device (cuInit returned %d)\n", r);
    return kExitSkip;
  }
  if (r != kSuccess) return Fail("cuInit", r);

  int version = 0;
  if ((r = cuDriverGetVersion(&version)) != kSuccess) return Fail("cuDriverGetVersion", r);
  std::printf("driver_cuda: %d.%d (%d)\n", version / 1000, version % 1000 / 10, version);
  if (version < kMinDriverCuda) {
    std::printf("error: the driver supports CUDA %d.%d, this project needs %d.%d or newer\n",
                version / 1000, version % 1000 / 10, kMinDriverCuda / 1000,
                kMinDriverCuda % 1000 / 10);
    return kExitBroken;
  }

  int count = 0;
  if ((r = cuDeviceGetCount(&count)) != kSuccess) return Fail("cuDeviceGetCount", r);
  std::printf("device_count: %d\n", count);
  if (count == 0) {
    std::printf("skip: the driver is loaded but no device is visible\n");
    return kExitSkip;
  }

  CUdevice device = 0;
  if ((r = cuDeviceGet(&device, 0)) != kSuccess) return Fail("cuDeviceGet", r);
  char name[256] = {};
  if ((r = cuDeviceGetName(name, static_cast<int>(sizeof name), device)) != kSuccess) {
    return Fail("cuDeviceGetName", r);
  }
  int major = 0;
  int minor = 0;
  if ((r = cuDeviceGetAttribute(&major, kAttrComputeMajor, device)) != kSuccess ||
      (r = cuDeviceGetAttribute(&minor, kAttrComputeMinor, device)) != kSuccess) {
    return Fail("cuDeviceGetAttribute", r);
  }
  std::printf("device 0: %s (compute capability %d.%d)\n", name, major, minor);

  // The primary context is the one the CUDA runtime and libraries use, so if it can be created
  // the device is usable by them as well.
  CUcontext context = nullptr;
  if ((r = cuDevicePrimaryCtxRetain(&context, device)) != kSuccess) {
    return Fail("cuDevicePrimaryCtxRetain", r);
  }
  if ((r = cuDevicePrimaryCtxRelease_v2(device)) != kSuccess) {
    return Fail("cuDevicePrimaryCtxRelease", r);
  }
  std::printf("context: created and released\n");
  return kExitOk;
}
```

**找到驱动库，登记测试。** `find_library` 在 Linux 上按默认路径找 `libcuda.so`；在 Windows 上提示去 `CUDA_PATH` 下的 `lib\x64` 找 `cuda.lib`。找不到不报错：配置打印一行说明，测试登记为 Disabled。找到了，就构建探针，链接这个库，并登记测试：`SKIP_RETURN_CODE 77` 让 CTest 把退出码 77 当作 Skipped，`LABELS gpu` 让你可以用 `ctest -L gpu` 单独运行它。

<!-- src: tools/gpu-probe/CMakeLists.txt#L15-L40 -->
```cmake
# The driver's own library: libcuda.so (the driver package provides the development link) or, on
# Windows, cuda.lib from the CUDA toolkit's import libraries. A machine without it is not an
# error here: the test is registered as disabled, so the rest of the project still builds.
find_library(COMFYSTUDY_CUDA_DRIVER_LIB NAMES cuda HINTS "$ENV{CUDA_PATH}/lib/x64")

if(NOT COMFYSTUDY_CUDA_DRIVER_LIB)
  message(STATUS "GPU: no CUDA driver library found (libcuda.so, or cuda.lib in CUDA_PATH), "
                 "the gpu_probe test is disabled")
  add_test(NAME gpu_probe COMMAND ${CMAKE_COMMAND} -E false)
  set_tests_properties(gpu_probe PROPERTIES DISABLED TRUE LABELS gpu)
  return()
endif()
message(STATUS "GPU: CUDA driver library ${COMFYSTUDY_CUDA_DRIVER_LIB}")

add_executable(gpu_probe probe.cpp)
target_link_libraries(gpu_probe PRIVATE "${COMFYSTUDY_CUDA_DRIVER_LIB}")
if(TARGET comfystudy_options)
  target_link_libraries(gpu_probe PRIVATE comfystudy_options)
elseif(MSVC)
  target_compile_options(gpu_probe PRIVATE /W4 /WX /permissive-)
else()
  target_compile_options(gpu_probe PRIVATE -Wall -Wextra -Werror)
endif()

add_test(NAME gpu_probe COMMAND gpu_probe)
set_tests_properties(gpu_probe PROPERTIES LABELS gpu SKIP_RETURN_CODE 77)
```

这个文件开头还有一个判断：只有它自己是最顶层的 CMake 项目时，才调用 `project()`。这样同一个文件既能被主项目 `add_subdirectory`，也能被 `check-env` 单独配置。作为子目录时，它沿用主项目的编译选项（`comfystudy_options`，也就是 `/W4 /WX`），单独配置时用自己的一套同等严格的选项。

**主项目加入探针。** 一行，没有条件：

<!-- src: CMakeLists.txt#L47-L49 -->
```cmake

```

**`check-env.ps1 -Gpu`。** 脚本先看 `nvidia-smi`：读显卡名、驱动版本，并从完整输出里读 `CUDA Version`（驱动支持的 CUDA 版本）。读到了，再把 `tools\gpu-probe` 配置、构建到一个临时目录，运行，最后删掉临时目录。配置、构建、运行任何一步失败，都打印那一步的名字和输出末尾，并把 `gpu` 记进缺失列表。

<!-- src: scripts/check-env.ps1#L54-L94 -->
```powershell
# -Gpu: the GPU as seen by the NVIDIA driver. nvidia-smi names the card and the driver; tools\gpu-probe
# (configured on its own, so it does not need the project's dependencies) calls the driver the way a
# program would. It needs the driver and cuda.lib from the CUDA toolkit, not nvcc.
if ($Gpu) {
  $smi = Get-Command 'nvidia-smi' -ErrorAction SilentlyContinue
  if ($null -eq $smi) {
    Write-Host 'MISSING nvidia-smi: no NVIDIA driver found'
    $missing.Add('nvidia-smi')
  } else {
    $card = First-Line 'nvidia-smi' @('--query-gpu=name,driver_version', '--format=csv,noheader')
    $cuda = ''
    if ((& nvidia-smi 2>&1 | Out-String) -match 'CUDA (?:UMD )?Version:\s*([0-9]+\.[0-9]+)') { $cuda = $Matches[1] }
    if ($card -eq '' -or $cuda -eq '') {
      Write-Host 'MISSING nvidia-smi: cannot read the GPU name, the driver or the CUDA version'
      $missing.Add('nvidia-smi')
    } else {
      Write-Host ("OK      nvidia-smi: {0}, supports CUDA {1}" -f $card, $cuda)
      $probeSource = Join-Path (Split-Path -Parent $PSScriptRoot) 'tools\gpu-probe'
      $probeBuild = Join-Path ([IO.Path]::GetTempPath()) ('gpu-probe-' + [Guid]::NewGuid().ToString('N'))
      $step = 'configure'
      $out = & cmake -S $probeSource -B $probeBuild -G Ninja 2>&1 | Out-String
      if ($LASTEXITCODE -eq 0 -and $out -notmatch 'no CUDA driver library found') {
        $step = 'build'
        $out = & cmake --build $probeBuild 2>&1 | Out-String
        if ($LASTEXITCODE -eq 0) {
          $step = 'run'
          $out = & (Join-Path $probeBuild 'gpu_probe.exe') 2>&1 | Out-String
        }
      }
      if ($step -eq 'run' -and $LASTEXITCODE -eq 0) {
        $device = ($out -split "`r?`n" | Where-Object { $_ -like 'device 0:*' } | Select-Object -First 1) -replace '^device 0:\s*', ''
        Write-Host ("OK      gpu: {0}, context created" -f $device)
      } else {
        $tail = ($out -split "`r?`n" | Where-Object { $_.Trim() -ne '' } | Select-Object -Last 3) -join ' | '
        Write-Host ("MISSING gpu: {0} failed: {1}" -f $step, $tail)
        $missing.Add('gpu')
      }
      Remove-Item -LiteralPath $probeBuild -Recurse -Force -ErrorAction SilentlyContinue
    }
  }
}
```

**改动检验。** 下面三项都是临时改动，验证后改回。

1. 把下限改成 `99000`：

```text
driver_cuda: 13.4 (13040)
error: the driver supports CUDA 13.4, this project needs 99.0 or newer
```

   退出码 1，`ctest` 里是 `***Failed`。

2. 把 `find_library` 的库名改成一个不存在的名字：

```text
-- GPU: no CUDA driver library found (libcuda.so, or cuda.lib in CUDA_PATH), the gpu_probe test is disabled
```

   配置和构建都成功，`ctest` 里是 `***Not Run (Disabled)`，只要还有别的测试在运行，`ctest` 的退出码就是 0。

3. 把 `cuDeviceGetCount` 的参数从 `int*` 改成 `long long`：

```text
probe.cpp(69): error C2664: 'CUresult cuDeviceGetCount(__int64)': cannot convert argument 1 from 'int *' to '__int64'
```

   编译就失败了。这说明编译器能抓住调用和声明不一致的情况。它抓不住“声明和驱动的实际接口不一致”，比如把某个参数写成别的整数类型，两边都能编译、链接，运行时才出错，所以才要在两个平台上真的运行一遍。

**`-Gpu` 不影响原来的检查。** 不带 `-Gpu` 的输出和上一章逐字相同（8 行 `OK` 加一行 `check-env: OK`），带 `-Gpu` 时多两行。

## 7. 技术资料

- CUDA Driver API：`cuInit`、`cuDriverGetVersion`、`cuDeviceGetCount`、`cuDeviceGet`、`cuDeviceGetName`、`cuDeviceGetAttribute`（`CU_DEVICE_ATTRIBUTE_COMPUTE_CAPABILITY_MAJOR` 是 75，`..._MINOR` 是 76）、`cuDevicePrimaryCtxRetain`、`cuDevicePrimaryCtxRelease_v2`；错误码 `CUDA_ERROR_NO_DEVICE` 是 100。以上数字取自 CUDA 工具包的 `cuda.h`，本章没有包含它，只在源码里抄了数字。
- 驱动版本号：`cuDriverGetVersion` 返回 `1000 * 主版本 + 10 * 次版本`。
- NVIDIA 的 CUDA 13.5 文档里，“13.x 的小版本兼容”要求驱动分支不低于 R580；本章的下限 13.0 与它对应。
- CMake：`find_library`（`NAMES`、`HINTS`）、`add_test`、`DISABLED`、`SKIP_RETURN_CODE`、`LABELS`；`ctest -L`。
- 设计取舍：
  - **用驱动，不用工具包。** 后面的章节才需要 `nvcc` 和 cuDNN，本章不检查它们，这样没有装工具包的机器也能通过。
  - **自己声明原型，不包含 `cuda.h`。** 两个平台同一份源码，代价是原型要自己保证正确。
  - **主上下文，不是 `cuCtxCreate`。** `cuCtxCreate` 有 `_v2`、`_v3`、`_v4` 几个版本，接口还变过；主上下文的两个函数更稳定，也正是运行时库用的那一个。
  - **没有开关，默认检测。** 缺库和没有设备都不算失败，所以没有显卡的 CI 容器也能配置和测试。
  - **被否决：** `LoadLibrary("nvcuda.dll")` 或 `dlopen("libcuda.so.1")`（要求用 CMake 链接，而且链接失败比运行时才发现更早暴露问题）；`find_package(CUDAToolkit)`（没有工具包时找不到，这台 Linux 机器上就是 FALSE）；在测试里 `enable_language(CUDA)`（要 `nvcc`）。

## 8. 常见问题与坑

- **配置时打印 `no CUDA driver library found`。** 没找到驱动库。Windows 上是没装 CUDA 工具包，或者 `CUDA_PATH` 没设；Linux 上是驱动包没有提供 `libcuda.so` 这个开发链接。测试会显示 Disabled。
- **`gpu_probe` 是 Skipped。** 驱动库有，但 `cuInit` 报没有设备，或者设备数是 0。检查驱动有没有装好、显卡有没有被禁用；在容器里要把设备透传进去。
- **`error: cuInit returned 100`。** 同上，设备不可见。别的数字去 CUDA 文档里查 `CUresult`：比如 3 是初始化失败，35 是驱动版本比运行时旧，999 是未知错误。
- **`error: the driver supports CUDA 12.x, this project needs 13.0 or newer`。** 驱动太旧，升级驱动。
- **`check-env.ps1 -Gpu` 报 `configure failed`。** 看后面附的输出：多半是没有在 MSVC 环境里运行（用 `scripts\dev.ps1`）。
- **`-Gpu` 报 `cannot read the GPU name`。** `nvidia-smi` 的输出格式变了，或者驱动出了问题；单独运行 `nvidia-smi` 看看。
- **驱动版本显示成 13.4，工具包是 13.5。** 正常，见第 6 节。
- **为什么 `check-env.ps1` 不检查 `nvcc`？** 这一章只管驱动层。用到 `nvcc` 的章节会自己检查。

## 9. 练习

练习：

1. 运行 `ctest --preset windows-debug -L gpu`，再运行 `ctest --preset windows-debug -LE gpu`，比较两次运行的测试个数。
2. 把探针的 `kMinDriverCuda` 改成比你的驱动高的值，看测试怎么失败；再改成 `12000`，想一想这样放宽下限对后面要用的 CUDA 13 的程序有什么风险。
3. 在 `probe.cpp` 里多读一个设备属性，比如 `CU_DEVICE_ATTRIBUTE_MULTIPROCESSOR_COUNT`（值是 16），打印出来；注意要自己查 `cuda.h` 里的数字。
4. 把 `cuDevicePrimaryCtxRelease_v2` 换成不带后缀的 `cuDevicePrimaryCtxRelease`，看看能不能链接、能不能运行；想一想这样做的风险。
5. 用 `dumpbin /exports C:\Windows\System32\nvcuda.dll` 看驱动导出了哪些带版本后缀的函数，数一数 `cuCtxCreate` 有几个版本。
6. 临时在设备管理器里禁用显卡（或者在没有显卡的机器上），重新配置并运行 `ctest`，看 `gpu_probe` 是 Skipped 还是 Disabled，对照第 8 节解释。
7. 让探针接受一个命令行参数，指定设备编号，而不是只用第 0 号；想一想退出码该怎么设计。
8. 想一想：为什么 `check-env` 单独配置探针，而不是直接构建主项目的 `gpu_probe` 目标？
