- 一句话目标：让所有 DLL 与可执行文件放在同一目录，提供 `deploy` 与 `check-dlls` 目标，启动时设置 DLL 搜索目录，并用 `--dependency-check` 列出程序加载的每个 DLL 的位置、版本和所属的 vcpkg 包

## 1. 本章目标与成果

到上一章为止，程序依赖了好几个 DLL：libcurl、zlib、spdlog、fmt，测试还有 GoogleTest。它们不是我们复制的，是 vcpkg 在每次链接之后自动复制到可执行文件旁边的。这一章把这件事“管起来”，回答三个问题：**程序到底用了哪些 DLL？它们从哪里来？会不会加载到不该加载的那一个？**

- **DLL 全部集中在 `build\<预设>\bin\`**，和 `comfystudy.exe`、测试程序放在一起。程序不依赖 `PATH`，拷贝整个 `bin` 目录就能运行。
- **`main` 的第一件事是 `InitSearchPath()`**：之后程序加载 DLL，只看自己的目录和系统目录，不再看 `PATH` 和当前目录。
- **`deploy` 目标**：在 `bin\` 里写一份 `dlls.manifest`，记下每个 DLL 的名字、SHA-256，以及它是哪个 vcpkg 包装进来的。
- **`check-dlls` 目标**：用 `dumpbin /dependents` 检查程序（包括间接依赖）需要的每个 DLL，要么是系统 DLL，要么在清单里、在 `bin` 里、内容和清单一致；否则列出问题并失败。
- **`comfystudy --dependency-check`**：列出当前进程加载的**每一个** DLL：用颜色标出它在哪里加载的，列出文件版本和所属的包。它只展示，不判断对错，退出码总是 0。
- 一个新模块 `dll_info`，负责上面这些，有 16 个单元测试，另外有两个 CTest 条目检查部署和输出。

## 2. 背景与概念

**Windows 怎么找 DLL。** 程序用到的 DLL 有两种来源。一种是**隐式链接**：链接时就把需要的 DLL 名字写进了 exe 的导入表（`libcurl-d.dll`、`KERNEL32.dll` 等），程序启动时，Windows 的加载器在 `main` 之前把它们全找出来、加载进来，找不到就直接不启动。另一种是**显式加载**：程序运行中调用 `LoadLibrary("xxx.dll")`，或者用延迟加载，第一次用到才加载。两种方式都要“按名字找文件”，而默认的搜索顺序很长：已知 DLL 列表、可执行文件所在的目录、系统目录、Windows 目录、当前目录、`PATH` 里的每一个目录……

这个顺序有两个麻烦：

- **结果取决于环境。** 你机器的 `PATH` 里碰巧有另一个版本的 `libcurl.dll`，程序可能加载的不是你构建时用的那一个。
- **安全隐患。** 当前目录和 `PATH` 里的目录，别人有可能放进同名的恶意 DLL（所谓 DLL 劫持）。

**本章的办法分两层。**

1. **把需要的 DLL 全部放在 exe 旁边。** exe 所在目录在搜索顺序里排得靠前，隐式链接的 DLL 在那里就能被找到。vcpkg 的 CMake 工具链文件默认就做这件事（叫 app-local 部署：每个目标链接完成后，把它依赖的 vcpkg DLL 复制到目标旁边），所以 `build\windows-debug\bin\` 里本来就有 `libcurl-d.dll` 这些文件。
2. **调用 `SetDefaultDllDirectories(LOAD_LIBRARY_SEARCH_APPLICATION_DIR | LOAD_LIBRARY_SEARCH_SYSTEM32)`。** 这个函数把“之后”的 DLL 搜索范围缩小到两处：程序自己的目录，和 `System32`。注意是“之后”：exe 的隐式导入在 `main` 之前就解析完了，这个函数管不到它们，它管的是以后的 `LoadLibrary`、延迟加载，以及这些 DLL 再去加载的 DLL。我们以后会加载 CUDA、ONNX Runtime 这类 DLL，这个设置就有用了。

**检查，而不是相信。** 光有约定不够，要有一个能反复运行的检查。我们需要回答两件事：

- “这个程序需要哪些 DLL？”：`dumpbin /dependents xxx.exe` 列出导入表里的 DLL 名字。DLL 自己也有导入表（libcurl 依赖 zlib），所以要递归检查。
- “它们是不是我们部署的那一份？”：把部署时每个 DLL 的 **SHA-256**（一种指纹：内容只要差一位，结果就完全不同）记在清单里，之后对比。

**怎么知道一个 DLL 属于哪个库。** vcpkg 在 `vcpkg_installed\vcpkg\info\` 里，为每个装好的包留了一份文件清单，名字是 `<包名>_<版本>_<triplet>.list`，里面是这个包装入的所有文件。`curl_8.23.0_x64-windows.list` 里有 `x64-windows/debug/bin/libcurl-d.dll`，所以 `libcurl-d.dll` 属于 `curl` 8.23.0。查这份清单是精确的，不靠猜名字。

**文件版本。** 每个 DLL 可以带一个版本资源，记录文件版本号（`8.23.0.0`）。`GetFileVersionInfoW` 读出它。有的 DLL 没有这个资源（比如 `fmtd.dll`），就显示 `-`。注意文件版本和 vcpkg 包的版本是两回事，二者经常不同，所以输出里两列都有。

**为什么只展示，不判断。** 一个进程里常常有我们管不了的 DLL：杀毒软件、录屏和游戏的悬浮层、输入法、调试器都会往进程里注入自己的 DLL。如果把“不在 bin 里”当成失败，程序在你的机器上就会时不时地“失败”，原因却和代码无关。所以 `--dependency-check` 只告诉你每个 DLL 在哪里，用颜色标出位置，哪里该怀疑由你判断；真正会让构建失败的，是 `check-dlls` 这类只看**我们自己的程序依赖**的检查。

```cpp
  std::string package;
```

**列出已加载的模块。** `EnumProcessModules` 返回进程里每个模块的句柄，再用 `GetModuleFileNameW` 换成路径。第一次给的缓冲区可能太小，`needed` 告诉我们实际需要多少，扩大后重来：

```cpp
std::vector<Module> LoadedModules() {
  std::vector<HMODULE> handles(256);
  DWORD needed = 0;
  for (;;) {
    const DWORD bytes = static_cast<DWORD>(handles.size() * sizeof(HMODULE));
    if (!::EnumProcessModules(::GetCurrentProcess(), handles.data(), bytes, &needed)) return {};
    if (needed <= bytes) break;
    handles.resize(needed / sizeof(HMODULE));
  }
  handles.resize(needed / sizeof(HMODULE));

  std::vector<Module> modules;
  for (HMODULE handle : handles) {
    std::wstring buffer(32768, L'\0');
    const DWORD length = ::GetModuleFileNameW(handle, buffer.data(), static_cast<DWORD>(buffer.size()));
    if (length == 0) continue;
    buffer.resize(length);
    Module module;
    module.path = FromWide(buffer);
    module.name = module.path.filename().string();
    modules.push_back(std::move(module));
  }
  return modules;
}
```

**判断位置。** 一个 DLL 在程序目录里、Windows 目录里，还是别处？关键是“在目录里”怎么判断。不能用字符串前缀：`D:\X\bin2\foo.dll` 以 `D:\X\bin` 开头，但它不在 `bin` 里。所以把路径拆成一段一段的目录名，全部转成小写（Windows 路径不分大小写），再比较“目录的各段是不是路径的前几段”：

```cpp
// The names of the directories in `path`, without the root and without empty names (which a
// trailing separator would produce).
std::vector<std::wstring> Parts(const std::filesystem::path& path) {
  std::vector<std::wstring> parts;
  parts.push_back(Lower(path.root_name().wstring()));
  for (const auto& part : path.relative_path()) {
    if (!part.empty()) parts.push_back(Lower(part.wstring()));
  }
  return parts;
}

// True if `path` is `directory` or somewhere below it.
bool IsInside(const std::filesystem::path& path, const std::filesystem::path& directory) {
  const auto dir = Parts(directory);
  const auto sub = Parts(path);
  return sub.size() >= dir.size() && std::equal(dir.begin(), dir.end(), sub.begin());
}
```

```cpp
std::string FileVersion(const std::filesystem::path& dll) {
  const std::wstring file = dll.wstring();
  DWORD ignored = 0;
  const DWORD size = ::GetFileVersionInfoSizeW(file.c_str(), &ignored);
  if (size == 0) return "-";
  std::vector<char> data(size);
  if (!::GetFileVersionInfoW(file.c_str(), 0, size, data.data())) return "-";
  VS_FIXEDFILEINFO* info = nullptr;
  UINT length = 0;
  if (!::VerQueryValueW(data.data(), L"\\", reinterpret_cast<void**>(&info), &length) || info == nullptr ||
      length < sizeof(VS_FIXEDFILEINFO) || info->dwSignature != 0xFEEF04BD) {
    return "-";
  }
  std::ostringstream out;
  out << HIWORD(info->dwFileVersionMS) << '.' << LOWORD(info->dwFileVersionMS) << '.'
      << HIWORD(info->dwFileVersionLS) << '.' << LOWORD(info->dwFileVersionLS);
  return out.str();
}
```

```cpp
Manifest ParseManifest(std::istream& in) {
  Manifest manifest;
  for (std::string line; std::getline(in, line);) {
    if (!line.empty() && line.back() == '\r') line.pop_back();
    if (line.empty() || line[0] == '#') continue;
    std::vector<std::string> fields;
    std::istringstream stream(line);
    for (std::string field; std::getline(stream, field, '\t');) fields.push_back(field);
    if (fields.size() != 4 || fields[0].empty()) continue;
    manifest[LowerAscii(fields[0])] = {fields[1], fields[2], fields[3]};
  }
  return manifest;
}
```

**打印。** 先把每个模块整理成一行：位置、名字（vcpkg 来的加 ` *`）、文件版本、包、路径。清单里找得到、而且包名不是 `-` 的才算 vcpkg 的 DLL。然后排序（程序目录在前，别处居中，Windows 目录在后，同组按名字），按各列的最大宽度对齐输出（`fmt::format` 的 `{:<{}}` 是“左对齐，宽度由后面的参数给出”）。

```cpp
// The color of a row: green for the program directory, gray for the Windows directory, yellow
// for everywhere else. fmt writes the ANSI codes (and the reset after the text) for us.
fmt::text_style Style(Location location) {
  switch (location) {
    case Location::App: return fmt::fg(fmt::terminal_color::green);
    case Location::Windows: return fmt::fg(fmt::terminal_color::bright_black);  // gray
    default: return fmt::fg(fmt::terminal_color::yellow);
  }
}
```

```cpp
void Print(std::ostream& out, const std::vector<Module>& modules, const Context& context) {
  std::vector<Row> rows;
  bool any_vcpkg = false;
  for (const Module& module : modules) {
    Row row;
    row.location = Classify(module.path, context.app_dir, context.windows_dir);
    row.name = module.name;
    row.version = FileVersion(module.path);
    row.package = "-";
    const auto found = context.manifest.find(LowerAscii(module.name));
    if (found != context.manifest.end() && found->second.package != "-") {
      row.name += " *";
      row.package = found->second.package;
      if (found->second.package_version != "-") row.package += " " + found->second.package_version;
      any_vcpkg = true;
    }
    row.path = module.path.string();
    rows.push_back(std::move(row));
  }

  // The program's directory first, the Windows directory last; by name inside each group.
  const auto rank = [](Location location) {
    return location == Location::App ? 0 : (location == Location::Other ? 1 : 2);
  };
  std::stable_sort(rows.begin(), rows.end(), [&](const Row& a, const Row& b) {
    if (rank(a.location) != rank(b.location)) return rank(a.location) < rank(b.location);
    return LowerAscii(a.name) < LowerAscii(b.name);
  });

  size_t name_width = 0, version_width = 0, package_width = 0;
  for (const Row& row : rows) {
    name_width = std::max(name_width, row.name.size());
    version_width = std::max(version_width, row.version.size());
    package_width = std::max(package_width, row.package.size());
  }

  // With color off, an empty style makes fmt write the text as it is.
  const auto paint = [&](Location location, const std::string& text) {
    return fmt::format(context.color ? Style(location) : fmt::text_style(), "{}", text);
  };
  for (const Row& row : rows) {
    const std::string line = fmt::format("{} {:<{}}  {:<{}}  {:<{}}  {}", Tag(row.location),
                                         row.name, name_width, row.version, version_width,
                                         row.package, package_width, row.path);
    out << paint(row.location, line) << '\n';
  }

  out << "\nLocation: " << paint(Location::App, "[bin ] program directory") << ", "
      << paint(Location::Windows, "[sys ] Windows directory") << ", "
      << paint(Location::Other, "[else] elsewhere") << '\n';
  if (any_vcpkg) out << "* = installed by vcpkg\n";
}
```

```cpp
void PrintDependencies(std::ostream& out, bool color) {
  Context context;
  const std::filesystem::path program = ProgramPath();
  context.app_dir = program.parent_path();
  context.windows_dir = WindowsDirectory();
  context.manifest = LoadManifest(context.app_dir / "dlls.manifest");

bool StdoutSupportsColor() {
  char* no_color = nullptr;
  size_t length = 0;
  const bool disabled = _dupenv_s(&no_color, &length, "NO_COLOR") == 0 && no_color != nullptr && *no_color != '\0';
  std::free(no_color);
  if (disabled) return false;

  const HANDLE handle = ::GetStdHandle(STD_OUTPUT_HANDLE);
  DWORD mode = 0;
  if (handle == INVALID_HANDLE_VALUE || !::GetConsoleMode(handle, &mode)) return false;  // not a console
  return ::SetConsoleMode(handle, mode | ENABLE_VIRTUAL_TERMINAL_PROCESSING) != 0;
}
```

**生成清单。** 先读 vcpkg 的 `.list` 文件，建一张表：DLL 文件名到“包名和版本”。包名和版本从文件名里用正则取出。再扫描 `bin` 里的每个 DLL，算 SHA-256，查表，查不到的包写 `-`：

<!-- src: tools/write-manifest.ps1#L11-L35 -->
```powershell
# DLL file name (lower case) -> package and version, from "<package>_<version>_<triplet>.list".
$owner = @{}
if (Test-Path -LiteralPath $VcpkgInfoDir) {
  foreach ($list in Get-ChildItem -LiteralPath $VcpkgInfoDir -Filter '*.list') {
    $m = [regex]::Match($list.BaseName, '^(?<package>.+?)_(?<version>[^_]+)_(?<triplet>[^_]+)$')
    if (-not $m.Success) { continue }
    foreach ($line in [IO.File]::ReadLines($list.FullName)) {
      if ($line -match '(?i)\.dll$') {
        $owner[[IO.Path]::GetFileName($line).ToLowerInvariant()] = $m.Groups['package'].Value, $m.Groups['version'].Value
      }
    }
  }
}

$lines = foreach ($dll in Get-ChildItem -LiteralPath $BinDir -Filter '*.dll' | Sort-Object { $_.Name.ToLowerInvariant() }) {
  $hash = (Get-FileHash -LiteralPath $dll.FullName -Algorithm SHA256).Hash.ToLowerInvariant()
  $package, $version = '-', '-'
  $found = $owner[$dll.Name.ToLowerInvariant()]
  if ($found) { $package, $version = $found }
  "{0}`t{1}`t{2}`t{3}" -f $dll.Name, $hash, $package, $version
}

$manifest = Join-Path $BinDir 'dlls.manifest'
[IO.File]::WriteAllText($manifest, (($lines -join "`n") + "`n"), (New-Object Text.UTF8Encoding $false))
Write-Host ("write-manifest: {0} DLL(s) -> {1}" -f @($lines).Count, $manifest)
```

**检查依赖。** 用一个队列做广度优先：先放进所有程序，每取出一个就用 `dumpbin /dependents` 列出它的依赖。每个依赖有三种结果：在清单里（检查文件存在、SHA-256 一致，然后把它也放进队列，检查它自己的依赖）；是系统 DLL（`System32` 里有，或者是 `api-ms-win-*`、`ext-ms-*` 这种名字）；都不是，记为问题。最后一次性列出所有问题：

<!-- src: tools/check-dlls.ps1#L27-L55 -->
```powershell

# Walk the dependencies: the programs first, then every DLL from the manifest that they pull in.
$queue = New-Object System.Collections.Generic.Queue[string]
$seen = @{}
foreach ($program in $programs) { $queue.Enqueue($program.FullName) }
while ($queue.Count -gt 0) {
  $file = $queue.Dequeue()
  $owner = Split-Path -Leaf $file
  $text = (& dumpbin /dependents $file 2>&1 | ForEach-Object { "$_" }) -join "`n"
  if ($LASTEXITCODE -ne 0) { Write-Host "check-dlls: FAILED, dumpbin failed on $owner"; exit 1 }
  $deps = [regex]::Matches($text, '(?m)^\s+(\S+\.dll)\s*$') | ForEach-Object { $_.Groups[1].Value }
  foreach ($dep in $deps) {
    $key = $dep.ToLowerInvariant()
    if ($manifest.ContainsKey($key)) {
      $path = Join-Path $BinDir $dep
      if (-not (Test-Path -LiteralPath $path)) {
        $problems.Add("${owner}: $dep is in the manifest but missing from $BinDir")
      } elseif ((Get-FileHash -LiteralPath $path -Algorithm SHA256).Hash.ToLowerInvariant() -ne $manifest[$key]) {
        $problems.Add("${owner}: $dep differs from the manifest (run the 'deploy' target again)")
      } elseif (-not $seen.ContainsKey($key)) {
        $seen[$key] = $true
        $queue.Enqueue($path)
      }
    } elseif ($key -like 'api-ms-win-*' -or $key -like 'ext-ms-*' -or (Test-Path -LiteralPath (Join-Path $system32 $dep))) {
      continue
    } else {
      $problems.Add("${owner}: $dep is neither a system DLL nor in the manifest")
    }
  }
```

## 7. 技术资料

- fmt 12.2.1（上一章起就在依赖里，是 spdlog 的依赖）：`fmt::format`、`fmt::text_style`、`fmt::fg`、`fmt::terminal_color`（`green`、`bright_black`、`yellow`），以及格式串里的 `{:<{}}`（动态宽度）。fmt 只写出 ANSI 控制码，不判断输出是不是终端。
- Windows API：`SetDefaultDllDirectories`（`LOAD_LIBRARY_SEARCH_APPLICATION_DIR`、`LOAD_LIBRARY_SEARCH_SYSTEM32`）、`EnumProcessModules`（`psapi.lib`）、`GetModuleFileNameW`、`GetWindowsDirectoryW`、`GetFileVersionInfoSizeW`、`GetFileVersionInfoW`、`VerQueryValueW`（`version.lib`）、`GetConsoleMode`/`SetConsoleMode`（`ENABLE_VIRTUAL_TERMINAL_PROCESSING`）、`_dupenv_s`。文档：Microsoft Learn 的 “Dynamic-Link Library Search Order” 和 “Dynamic-link library security”。
- 工具：`dumpbin /dependents`（随 MSVC 提供，要在 MSVC 环境里运行；`scripts\dev.ps1` 已经配好）。PowerShell 的 `Get-FileHash -Algorithm SHA256`。
- vcpkg：app-local 部署（`VCPKG_APPLOCAL_DEPS`，工具链文件默认开启）；已安装包的文件清单在 `<安装目录>\vcpkg\info\<包>_<版本>_<triplet>.list`。
- 退出码 `0xC0000135`（`STATUS_DLL_NOT_FOUND`）。
- 设计取舍：
  - **`--dependency-check` 只展示，不判断。** 进程里常有外部注入的 DLL，把“不在 bin 里”当失败会产生和代码无关的失败。判断交给读的人，位置用颜色和标签标出来。代价是它不能在 CI 里单独当作“通过或失败”的依据；真正的门禁是 `check-dlls`。
  - **颜色用 fmt，不自己拼控制码。** fmt 已经在依赖里，不增加库；样式有名字（`terminal_color::green`），不用记 `[32m`。判断“能不能用颜色”fmt 不管，所以 `StdoutSupportsColor` 仍然是自己写的。被否决的是 rang、termcolor：它们会自动判断终端，但要多一个依赖，而且上面这几十行已经有测试。
  - **标签文字和颜色同时给。** 只靠颜色，重定向到文件或者色盲用户就看不出位置；所以每行前面有 `[bin ]`、`[sys ]`、`[else]`。
  - **没有 `--load` 之类让程序加载任意 DLL 的选项。** 让程序按用户给的路径加载 DLL，等于给它开了一个执行任意代码的口子，而这一章的目的是反过来收紧 DLL 的来源。
  - **清单在构建时生成，不在运行时查 vcpkg。** 运行时的程序可能被复制到没有 `vcpkg_installed` 的机器上；清单随着 `bin` 目录一起走。
  - **包名只来自清单；查不到就是 `-`。** 不靠文件名猜。系统 DLL 也显示 `-`，位置标签已经说明了它们是什么。
  - **`check-dlls` 递归检查。** 只看 exe 的导入表会漏掉间接依赖。
  - **`deploy` 默认不跟着每次构建运行。** 每次构建都重算全部 SHA-256 没有必要；需要时运行目标，`ctest` 里的 `check_dlls` 会替你先运行它。
  - **不复制调试版 CRT。** `vcruntime140d.dll`、`ucrtbased.dll` 等在装了 Visual Studio 的机器上已经在 `System32` 里，`check-dlls` 把它们当系统 DLL。要把 Debug 版部署到没有 VS 的机器上是另一个问题，调试版本来就不是用来发布的。
  - **被否决：** 在 `bin` 之外的目录里找“stray”（杂散）DLL 并让程序启动失败（外部注入会造成误报）；用 `LoadLibrary` 加载一个测试用 DLL 来演示（见上面的 `--load`）；把 `PATH` 清掉再运行测试（只对当前这个进程有效，不能代表用户机器）。
- 当前依赖的 DLL，在 Debug 下是 `libcurl-d.dll`、`libzd.dll`、`spdlogd.dll`、`fmtd.dll`，测试多 `gtest.dll`、`gtest_main.dll`；Release 下没有 `d` 后缀的名字不同，清单会随构建重新生成。

## 8. 常见问题与坑

- **运行程序没有任何输出，退出码是 `-1073741515`（`0xC0000135`）。** 缺 DLL。用 `dumpbin /dependents` 看 exe 要哪些，再看它们的依赖。最常见的原因是只复制了 exe，没复制整个 `bin` 目录。
- **`check-dlls` 报 `differs from the manifest`。** 依赖库重新构建或升级过，`bin` 里的 DLL 变了而清单还是旧的。重新运行 `deploy`。
- **`check-dlls` 报 `is neither a system DLL nor in the manifest`。** 有一个 DLL 既不是系统的，也没在清单里。要么是新引入的依赖还没运行 `deploy`，要么是依赖了一个根本没有部署到 `bin` 的 DLL（比如装在别处的 CUDA 运行库）。
- **`check-dlls` 报 `dumpbin failed` 或找不到 dumpbin。** 没在 MSVC 环境里运行。用 `scripts\dev.ps1`，或者 x64 Native Tools 命令提示符。
- **`--dependency-check` 里没有 `*`。** 没运行过 `deploy`，没有清单。
- **输出里有一个黄色的 `[else]` DLL。** 多半是杀毒、悬浮层、输入法之类注入进来的；看路径就能判断。如果是你自己依赖的库，说明它没有被部署到 `bin`。
- **颜色显示成一堆 `←[32m`。** 控制台不认 ANSI 控制码。新版 Windows Terminal 认；旧的 `cmd` 窗口里，程序会自己尝试开启，如果还是失败就设 `NO_COLOR=1`，或者把输出重定向到文件。
- **想让程序加载 `PATH` 里的 DLL，却加载不到。** `InitSearchPath()` 之后，显式加载只在程序目录和 `System32` 里找。要加载别处的 DLL，先 `AddDllDirectory` 把那个目录加进来，或者把 DLL 放进 `bin`。
- **有的 DLL 版本显示 `-`。** 它没有版本资源（比如 `fmtd.dll`），不是读取失败。
- **`gtest.dll` 不在清单里。** 清单只记录运行 `deploy` 时 `bin` 里已有的 DLL；测试程序没构建过，GoogleTest 的 DLL 就还没被复制过来。完整构建一次，再运行 `deploy`。
- **Release 构建的 `bin` 在 `build\windows-release\bin`。** 用 `cmake --build --preset windows-release --target deploy` 为它生成清单；每个预设有自己的清单。

## 9. 练习

练习：

1. 运行 `--dependency-check`，数一数 `[bin ]`、`[sys ]` 和 `[else]` 各有几行；有 `[else]` 的话，看看它们是什么。
2. 把 `NO_COLOR=1` 设上再运行，再把输出重定向到文件（`> out.txt`），确认文件里没有 `←[` 控制码。
3. 删掉 `dlls.manifest`，运行 `--dependency-check`，看看 `*` 和包那一列的变化；再运行 `deploy` 恢复。
4. 用 `dumpbin /dependents` 看 `spdlogd.dll` 和 `fmtd.dll`，画出这几个库的依赖关系，再对照 `check-dlls` 的检查顺序。
5. 把 `libzd.dll` 在 `bin` 里改个名，运行 `check-dlls`，再运行 `comfystudy.exe`，比较两次的结果，想一想后者为什么没有任何输出。
6. 给 `Classify` 加一个测试：`D:\X\bin\..\bin2\foo.dll`（含 `..`），想一想它该算在哪一类，当前的实现会怎样；怎样用 `lexically_normal` 修好它？
7. 在 `vcpkg.json` 里加一个依赖（比如 `fmt` 之外的 `zstd`），重新构建，运行 `deploy` 和 `--dependency-check`，确认新 DLL 出现并带 `*`，包是你加的那个。
8. 给 `--dependency-check` 加一个 `--json` 开关，改用 nlohmann/json 输出；想一想颜色和图例应该怎么处理。
9. 在 `check-dlls.ps1` 里，把“不在清单里的系统 DLL 之外的依赖”扩展成可以从一个允许列表里放行（比如 `nvcuda.dll`）；想一想这个允许列表该放在哪里。
10. 想一想：为什么 `InitSearchPath()` 不能替代“把 DLL 放在 exe 旁边”？反过来，只放在 exe 旁边，又留下了什么风险？
