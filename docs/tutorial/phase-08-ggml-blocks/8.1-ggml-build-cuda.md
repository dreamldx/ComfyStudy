设计备忘（细节待定，写到本章时再确认）：

- 固定使用 stable-diffusion.cpp 子模块里的 `leejet/ggml` 分叉（`sd.cpp` 分支），并固定到具体提交，让进程里只有一份 ggml，13.1 集成 stable-diffusion.cpp 时不会出现两份冲突。
- 固定的版本（2026-11-24 核对）：ggml 为 `eeda9ec48fc84a3df0bb9dcc19ae9053075a2539`，对应 stable-diffusion.cpp 的 `3b12781fac1a22eda27ad0f08d0884ef816f24d7`（2026-11-23）。两者要成对固定；动手时先核对子模块指针是否变化，变了就一起更新并重新验证。
- 理由：stable-diffusion.cpp 默认就用这个分叉；据 stable-diffusion.cpp 的 `docs/build.md`（2026-11-24 查阅）：默认（`SD_USE_UPSTREAM_GGML=OFF`）用打过补丁的 ggml；改用上游 ggml 时，FP8 权重在加载时转成 F16（文件里每个元素 1 字节，内存与显存里 2 字节），INT8 tensorwise / ConvRot 被禁用，上游还可能缺少部分算子与性能优化。以实际固定的提交为准。
- 代价：阶段 8、9 用的不是纯上游 ggml，教程里要说明并固定提交；升级子模块要谨慎。教程里面向上游接口写的代码能否直接编译，需要实际验证。
- 不要使用 Debian 等发行版自带的 ggml 包。
