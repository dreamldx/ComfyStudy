# 1.4 工具运行时：注册、校验与执行

- 状态：未开始 ｜ 类型：主线 ｜ tag：`chapter-1.4-tool-runtime` ｜ 上一 tag：`chapter-1.3-tool-calling`
- 所属阶段：[阶段 1：LLM 与对话通道](README.md)
- 一句话目标：把工具做成一层运行时：工具定义只写一份（JSON Schema、参数解析和说明文字由同一份 C++ 定义生成），所有工具来源（原生、Skill、MCP、脚本）通过统一的 `ToolSource` 接口注册；执行前校验参数，执行时有超时和并发策略，结果统一处理（过大截断、错误作为结果回传），工具按只读、有副作用、危险分类

待写。（要点：工具定义的单一来源：工具的 JSON Schema、参数解析和说明文字从同一份 C++ 定义生成，避免三处不同步；统一的 `ToolSource` 接口：原生 C++ 工具、Skill（1.5）、MCP（支线 llm-2.6）、脚本（支线 llm-5.5）都通过它注册进同一个运行时，Agent 循环（1.3）只认运行时；执行前按 JSON Schema 校验参数；畸形调用（不合法的 JSON、不存在的工具名）当错误回传，让模型重试；执行策略：每个工具的超时、同类工具的并发上限；结果的处理：太大就截断并告诉模型被截断了；出错时把错误作为结果回传，不抛异常；结果用内容块表示（文本、图片，见 1.2）；工具的副作用分类：只读、有副作用、危险三类，分类决定能不能并行、要不要用户确认、失败后能不能重试；工具的开始、结束、产物都作为 Agent 事件（见 1.3）发出；测试：用假工具覆盖截断、出错、超时和畸形调用。）
