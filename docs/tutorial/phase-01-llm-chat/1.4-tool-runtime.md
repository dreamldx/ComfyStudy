# 1.4 工具运行时：注册、校验与执行

- 状态：已打 tag ｜ 类型：主线 ｜ tag：`chapter-1.4-tool-runtime` ｜ 上一 tag：`chapter-1.3-tool-calling`
- 所属阶段：[阶段 1：LLM 与对话通道](README.md)
- 一句话目标：把工具做成一层运行时：所有来源（C++ 原生、以后的 Skill、MCP、脚本）走同一个 `ToolSource` 接口；每次调用先按 Schema 校验参数（一次列出全部问题），带着时间限制执行，结果过长就在字符边界截断，出错都作为结果回传；工具定义只写一份（C++ 结构体加 Glaze 生成 Schema）；工具按只读、有副作用、危险分类，危险的默认拒绝

## 1. 本章目标与成果

1.3 的循环已经能让模型调用工具，但工具是“一张手写的表”：一个工具的参数说明手写一遍，参数检查又在工具函数里手写一遍；一个工具卡住，整个 Turn 就卡住；工具返回一大堆文字，也原样塞进对话。这一章把工具做成一层运行时，循环不用改，只换掉 `ToolSet` 的实现。做完后你会得到：

- **`ToolSource` 接口：** 所有来源的工具都从这里进来。现在有 C++ 写的原生工具，1.5 的 Skill、以后的 MCP 和脚本都是它的实现，运行时只认这一个接口。
- **`ToolRuntime`：** 实现 `ToolSet`，每次调用都先做同样几件事：找到工具；参数是不是合法 JSON；危险的工具默认不让跑；按 Schema 检查参数；带着时间限制去执行；结果太长就截断。出什么错都是一个结果交给模型，不抛异常（取消除外）。
- **校验器 `schema.h`：** 对 JSON Schema 的常用子集检查参数，一次列出所有问题，每个问题带着出错的位置，比如 `arguments.ms: must be at most 60000 (got 90000)`。不认识的关键字不检查，登记时会警告。
- **工具定义只写一份：** 参数写成一个 C++ 结构体，Glaze 从它写出 JSON Schema，也用它读参数；说明和范围就写在结构体旁边。没有结构体的来源（Skill、MCP）仍可以用手写的 Schema。
- **副作用分类：** 只读、有副作用、危险。运行时只做一件事：危险的工具默认拒绝。
- **四个玩具工具：** `add`、`sleep`、`repeat`（返回很长的文字，用来看截断）、`shutdown`（危险，用来看拒绝）。
- 两个新设置：`tool_timeout_ms`（默认 30000）和 `tool_result_max_bytes`（默认 16384）。41 个新测试，现在一共 258 个。

先看效果（配置文件里已经写好密钥和模型，这里用的是 Anthropic）：

## 2. 背景与概念

**1.3 的工具表差在哪里。** 1.3 的 `ToolTable` 够用，但每个工具都自己负责三件事：说明模型能传什么（Schema，手写），检查模型传来的东西（函数里手写），出了错怎么回话。三处写的是同一件事，改一处忘了另一处，模型就会被告知一套、实际要求另一套。工具运行时把这些收到一个地方做，工具函数只管干活。

**工具从哪里来。** 以后工具会有四种来源：写在程序里的 C++ 函数、Skill 带来的、MCP 服务提供的、脚本里调用的。它们的共同点只有“有一批工具，每个有名字、说明、参数的 Schema，能被调用”。所以接口只有两个函数：`Specs()` 说现在有哪些工具，`Call()` 去执行。`Specs()` 每个 Step 都会被重新问一次，因为 Skill 可以在回合中间加载新工具。

**参数怎么检查。** 模型传来的参数是它“猜”的：缺字段、类型不对、数字超范围都常见。检查放在运行时，对所有来源一视同仁，而且做在执行之前：不合格的参数连工具都不用叫醒。错误信息要写给模型看：它读到 `arguments.ms: must be at most 60000 (got 90000)` 就知道怎么改。校验器是自己写的，只认 JSON Schema 的一个子集：`type`、`properties`、`required`、`additionalProperties`（只认 `false`）、`items`、`minItems`、`maxItems`、`enum`、`const`、`minimum`、`maximum`、`minLength`、`maxLength`，还有 Glaze 写枚举用的 `oneOf` 加 `const`。其他关键字（`$ref`、`anyOf`、`pattern`、`format` 等）不检查：这样 MCP 工具带来一个复杂的 Schema 也不会被误拒，代价是那部分不检查。为了不让这件事悄悄发生，运行时在第一次提供一个工具时，把它的 Schema 里没检查的关键字打进日志。

**Schema 从结构体来。** Glaze 能从 C++ 结构体写出 JSON Schema（`glz::write_json_schema`），字段的说明和范围写在结构体旁边的 `glz::json_schema` 特化里。但它写出来的东西不能原样交给模型：数字字段是 `{"$ref": "#/$defs/double"}`，`$defs` 里写着这个 C++ 类型的整个范围（比如 `-1.7976931348623157E308` 到 `1.7976931348623157E308`），根上还有 `title`。`schema::Normalize` 把它整理成模型要看的样子：展开 `$ref`，去掉 `$defs` 和 `title`，数字类型只留 `type`，字段上自己写的范围保留。Glaze 在读参数时不检查 `minimum` 和 `maximum`（读 70000 进一个最大 60000 的字段，它不报错），所以范围由运行时的校验器管。

**时间限制。** 一个工具如果卡住，整个 Turn 就卡住，Discord 机器人就不回话了。运行时给每个调用一个期限：工具自己指定的，没有就用 `tool_timeout_ms`（默认 30 秒，0 表示不限）。超时不是异常，是一个错误结果：“工具 X 没有在 N 毫秒内完成，已被停止”。外部取消（Ctrl+C）和超时要分清：取消仍然一路往上抛，让整个 Turn 结束。

**截断。** 一个返回 10 万字节的工具，会把这 10 万字节全部放进下一次请求，花钱，还可能超过模型的上下文。运行时把结果限制在 `tool_result_max_bytes`（默认 16 KB），在 UTF-8 字符边界上截断（不能把一个汉字切成两半，否则请求体就不合法了），并在末尾写明“显示了多少、一共多少字节”，模型因此知道自己看到的是一部分。

**分类。** 每个工具有一个 `Effect`：`kReadOnly`（只看，不改）、`kSideEffect`（会改变什么）、`kDangerous`（做了就收不回来）。不写的话是 `kSideEffect`：不确定就别当它无害。这一章运行时只用它做一件事：`kDangerous` 的工具默认拒绝，构造运行时时明确允许才跑。其余用途留给后面：只读的才可以并行（支线 llm-2.1），要不要问用户确认（支线 llm-1.1），失败后能不能重试。

**这一章不做的。** 一个 Step 里的多个调用仍然按顺序执行，所以也没有“同类工具的并发上限”：循环不并行，这个上限没有任何场景能触发，也就没法测试。并行执行是支线 llm-2.1 的事，分类和结果里的 `effect` 字段就是为它准备的。

## 4. 关键代码讲解

**分类和结果。** `ToolResult` 多了两个字段：`truncated`（文字被截断了）和 `effect`（这个工具的分类），都由运行时填。钩子能看到它们，不用改钩子的接口。

```cpp
// What a tool does to the world. Not assumed to be harmless: a tool that says nothing is kSideEffect.
//   kReadOnly    only looks (a sum, a search, a file read); several can run at the same time and a failed
//                one can be tried again
//   kSideEffect  changes something (writes a file, sends a message)
//   kDangerous   what cannot be undone (deletes, pays, shuts down); the runtime refuses to run it unless
//                it was told to allow it
enum class Effect { kReadOnly, kSideEffect, kDangerous };

const char* EffectName(Effect effect);  // "read-only", "side-effect", "dangerous"

// What running a tool gave. A failure is a result too (is_error), not an exception: the model is
// told what went wrong and can try again. `truncated` and `effect` are filled in by the runtime (chapter
// 1.4): the text was cut because it was too long, and how the tool is classified.
struct ToolResult {
  std::string text;
  bool is_error = false;
  bool truncated = false;
  Effect effect = Effect::kSideEffect;
};
```

**一个工具和一个来源。** `ToolSpec` 是运行时和模型需要知道的关于一个工具的全部。`effect` 默认是 `kSideEffect`。`ToolSource` 只有两个函数；运行时调用 `Call` 之前已经按 Schema 检查过参数，来源可以相信参数合格。`RuntimeOptions` 是运行时自己的三个旋钮。

```cpp
struct ToolSpec {
  std::string name;
  std::string description;
  json::Value parameters;                  // the JSON Schema of the arguments (an object schema)
  Effect effect = Effect::kSideEffect;     // not assumed to be harmless
  std::chrono::milliseconds timeout{0};    // zero: the runtime's default
};

// Where tools come from. A source says which tools it has now (this may change from one call to the next:
// a Skill that is loaded adds some) and runs a call. The runtime checks the arguments before Call, so a
// source can rely on them fitting the schema it gave. Call may throw: the runtime turns that into an error
// result (a cancellation is the one exception that goes on).
class ToolSource {
 public:
  virtual ~ToolSource() = default;
  virtual std::vector<ToolSpec> Specs() const = 0;
  virtual boost::asio::awaitable<ToolResult> Call(const std::string& name, const json::Value& arguments) = 0;
};

struct RuntimeOptions {
  std::chrono::milliseconds timeout{30000};  // for a call whose tool has no time limit of its own; zero: none
  std::size_t max_result_bytes = 16384;      // longer results are cut (at the end of a UTF-8 character)
  bool allow_dangerous = false;              // run the tools that are kDangerous
};
```

**运行时。** `AddSource` 在加入来源时检查名字有没有重复；`Definitions` 把所有来源的工具合起来，每个 Step 都会被循环重新问一次。

```cpp
class ToolRuntime final : public ToolSet {
 public:
  explicit ToolRuntime(RuntimeOptions options = {});

  // Throws std::invalid_argument when the source has a tool whose name another source already has.
  void AddSource(std::shared_ptr<ToolSource> source);

  // How the tool is classified, or nothing when there is no such tool now.
  std::optional<Effect> EffectOf(const std::string& name) const;

  // The tools of all the sources, in the order the sources were added; when two tools have the same name
  // (a source changed its mind after AddSource) the first one wins. Logs, once for each tool, the schema
  // keywords that are not checked (schema.h).
  std::vector<llm::ToolDefinition> Definitions() const override;

  // In order: find the tool; refuse a call whose arguments were not valid JSON; refuse a dangerous tool
  // (unless allowed); check the arguments against the schema (every problem is listed); call it with a
  // time limit; cut a result that is too long. Never throws, except for a cancellation.
  boost::asio::awaitable<ToolResult> Run(const llm::ToolCallBlock& call) override;

 private:
  struct Found {
    std::shared_ptr<ToolSource> source;
    ToolSpec spec;
  };
  std::optional<Found> Find(const std::string& name) const;

  RuntimeOptions options_;
  std::vector<std::shared_ptr<ToolSource>> sources_;
  mutable std::vector<std::string> warned_;  // tools whose unchecked keywords were already logged
};
```

**一次调用的全过程。** 顺序是有意安排的：先找工具，找不到就把现有的工具名列给模型（模型常常是拼错了名字）；参数不是合法 JSON 时，带上模型发来的原文；危险的工具在**校验之前**就拒绝，没必要为一个不会跑的调用去校验；校验不通过就列出全部问题；然后才带着期限去执行，最后截断。

<!-- src: src/tool_runtime.cpp#L165-L197 -->
```cpp
asio::awaitable<ToolResult> ToolRuntime::Run(const llm::ToolCallBlock& call) {
  const auto found = Find(call.name);
  if (!found) {
    std::string known;
    for (const std::shared_ptr<ToolSource>& source : sources_) {
      for (const ToolSpec& spec : source->Specs()) known += (known.empty() ? "" : ", ") + spec.name;
    }
    co_return Error("there is no tool called \"" + call.name + "\"; the tools are: " + known, Effect::kSideEffect);
  }
  const Effect effect = found->spec.effect;

  if (call.arguments.is_null()) co_return Error("the arguments are not valid JSON: " + call.arguments_text, effect);

  if (effect == Effect::kDangerous && !options_.allow_dangerous) {
    co_return Error("the tool \"" + call.name + "\" is classified as dangerous, and dangerous tools are not allowed to run", effect);
  }

  const std::vector<std::string> problems = schema::Validate(found->spec.parameters, call.arguments);
  if (!problems.empty()) {
    std::string text = "the arguments of \"" + call.name + "\" do not fit its schema:";
    for (const std::string& problem : problems) text += "\n- " + problem;
    co_return Error(text, effect);
  }

  const std::chrono::milliseconds timeout = found->spec.timeout.count() > 0 ? found->spec.timeout : options_.timeout;
  ToolResult result = co_await Execute(found->source, call.name, call.arguments, timeout, effect);
  result.effect = effect;
  if (result.text.size() > options_.max_result_bytes) {
    result.text = Cut(result.text, options_.max_result_bytes);
    result.truncated = true;
  }
  co_return result;
}
```

**执行：卫兵和期限。** 期限用 Asio 的 `||` 实现：调用和一个定时器同时开始，谁先完成，另一个就被取消。有一点要注意：调用自己放在一个单独的协程 `Guarded` 里，工具抛出的任何异常都在那里变成错误结果，只有取消会从里面出来。这是实测之后才这样写的：直接把会抛异常的工具放进 `||`，工具一抛异常，运行时要等定时器走完（默认 30 秒）才返回，错误信息也变成了“超时”。放进 `Guarded` 之后，抛出的异常在 `||` 之前就处理掉了。

<!-- src: src/tool_runtime.cpp#L47-L84 -->
```cpp
// Calls the tool; whatever it throws becomes an error result, except a cancellation. This is a coroutine of
// its own, and the time limit is put around it (below), so that nothing but a cancellation ever leaves it
// as an exception: `a || b` does not cope well with an operand that throws before its first suspension
// (the timer was left running until it ran out).
asio::awaitable<ToolResult> Guarded(std::shared_ptr<ToolSource> source, std::string name, json::Value arguments, Effect effect) {
  try {
    co_return co_await source->Call(name, arguments);
  } catch (const boost::system::system_error& e) {
    if (IsCancellation(e)) throw;
    co_return Error(std::string("the tool failed: ") + e.what(), effect);
  } catch (const std::exception& e) {
    co_return Error(std::string("the tool failed: ") + e.what(), effect);
  }
}

// Calls the tool and puts a time limit on it. The arguments are taken by value: this coroutine outlives the
// caller's references while `||` runs the call and the timer next to each other.
asio::awaitable<ToolResult> Execute(std::shared_ptr<ToolSource> source, std::string name, json::Value arguments,
                                    std::chrono::milliseconds timeout, Effect effect) {
  if (timeout.count() == 0) co_return co_await Guarded(std::move(source), std::move(name), std::move(arguments), effect);
  try {
    auto outcome = co_await (Guarded(source, name, std::move(arguments), effect) || Deadline(timeout));
    if (outcome.index() == 1) {
      co_return Error("the tool \"" + name + "\" did not finish within " + std::to_string(timeout.count()) + " ms and was stopped", effect);
    }
    co_return std::move(std::get<0>(outcome));
  } catch (const asio::multiple_exceptions& e) {
    // a cancellation from outside reached the call and the timer, and both ended with it
    if (FirstIsCancellation(e)) throw boost::system::system_error(asio::error::operation_aborted);
    try {
      std::rethrow_exception(e.first_exception());
    } catch (const std::exception& first) {
      co_return Error(std::string("the tool failed: ") + first.what(), effect);
    } catch (...) {
      co_return Error("the tool failed", effect);
    }
  }
}
```

**截断。** `end` 从上限开始，只要 `text[end]` 是 UTF-8 的续字节（高两位是 `10`），就往回退，直到落在一个字符的开头。

<!-- src: src/tool_runtime.cpp#L86-L92 -->
```cpp
// At most `limit` bytes of `text`, never ending in the middle of a UTF-8 character, and a line that says how
// much was left out.
std::string Cut(const std::string& text, std::size_t limit) {
  std::size_t end = limit;
  while (end > 0 && (static_cast<unsigned char>(text[end]) & 0xC0u) == 0x80u) --end;  // text[end] would start the cut-off part
  return text.substr(0, end) + "\n[truncated: showing " + std::to_string(end) + " of " + std::to_string(text.size()) + " bytes]";
}
```

**把 Glaze 写的 Schema 整理给模型。** `Resolve` 做三件事：遇到 `$ref` 就换成它指向的定义（数字类型的定义只取 `type`，不要 C++ 类型的整个范围），然后把写在 `$ref` 旁边的东西（说明、自己写的范围）叠上去，所以字段上的 `minimum` 和 `maximum` 会盖过定义里的；`$defs` 和 `title` 丢掉；`properties` 里的键是字段名，一个字段可以叫 `title`，所以进入 `properties` 时不去掉键。

<!-- src: src/schema.cpp#L25-L54 -->
```cpp
Value Resolve(const Value& node, const Value& definitions, int depth, bool in_properties) {
  if (depth > kMaxDepth) throw std::runtime_error("the schema refers to itself, or is nested too deeply");
  if (node.is_array()) {
    Value out = json::Array();
    for (const Value& item : node.get_array()) json::Push(out, Resolve(item, definitions, depth + 1, false));
    return out;
  }
  if (!node.is_object()) return node;

  Value out = json::Object();
  const Value* reference = in_properties ? nullptr : json::Find(node, "$ref");
  if (reference != nullptr && reference->is_string()) {
    const std::string target = reference->get<std::string>();
    const std::string prefix = "#/$defs/";
    if (target.compare(0, prefix.size(), prefix) != 0) throw std::runtime_error("cannot resolve the reference " + target);
    const std::string name = target.substr(prefix.size());
    const Value* definition = json::Find(definitions, name);
    if (definition == nullptr) throw std::runtime_error("the schema has no definition called " + name);
    const Value resolved = Resolve(*definition, definitions, depth + 1, false);
    for (const auto& [key, member] : resolved.get_object()) {
      if (IsArithmeticDefinition(name) && key != "type") continue;  // the range of the C++ type is no information
      out.get_object()[key] = member;
    }
  }
  for (const auto& [key, member] : node.get_object()) {
    if (!in_properties && (key == "$ref" || key == "$defs" || key == "title")) continue;
    out.get_object()[key] = Resolve(member, definitions, depth + 1, !in_properties && key == "properties");
  }
  return out;
}
```

```cpp
void Check(const Value& schema, const Value& value, const std::string& path, std::vector<std::string>& problems) {
  if (!schema.is_object()) return;

  if (const Value* type = json::Find(schema, "type")) {
    std::vector<std::string> types;
    if (type->is_string()) types.push_back(type->get<std::string>());
    if (type->is_array()) {
      for (const Value& t : type->get_array()) {
        if (t.is_string()) types.push_back(t.get<std::string>());
      }
    }
    bool matches = types.empty();
    for (const std::string& t : types) matches = matches || TypeMatches(t, value);
    if (!matches) {
      std::string wanted;
      for (std::size_t i = 0; i < types.size(); ++i) wanted += (i == 0 ? "" : " or ") + (types.size() == 1 ? WithArticle(types[i]) : (types[i] == "null" ? types[i] : "a " + types[i]));
      problems.push_back(path + ": must be " + wanted + " (got " + Describe(value) + ")");
      return;  // what follows assumes the type is right
    }
  }

  if (const Value* constant = json::Find(schema, "const")) {
    if (!(*constant == value)) problems.push_back(path + ": must be " + json::Dump(*constant) + " (got " + json::Dump(value) + ")");
  }
  std::vector<Value> storage;
  if (const Value::array_t* choices = Choices(schema, storage)) {
    bool found = false;
    std::string list;
    for (const Value& choice : *choices) {
      found = found || choice == value;
      list += (list.empty() ? "" : ", ") + json::Dump(choice);
    }
    if (!found) problems.push_back(path + ": must be one of " + list + " (got " + json::Dump(value) + ")");
  }
```

## 7. 技术资料

- Glaze 9.1.0：`glz::write_json_schema<T, glz::opts{.error_on_missing_keys = true}>()`、`glz::read<glz::opts{.error_on_unknown_keys = false, .error_on_missing_keys = true}>`、`glz::json_schema<T>` 特化里的 `glz::schema`（`description`、`minimum`、`maximum`、`minLength`、`maxLength`）、`glz::format_error`。Glaze 读结构体时不检查 `minimum` 和 `maximum`。
- Boost.Asio 1.92.0：`awaitable_operators` 的 `||`（谁先完成，另一个被取消，返回 `std::variant`），`asio::multiple_exceptions`。
- JSON Schema：校验器认的关键字见第 2 节；`$schema`、`title`、`description`、`default`、`examples`、`$comment`、`$id` 是注释，不算“没检查”。
- 设计取舍：
  - **运行时统一校验，不让工具各管各的。** 一个地方，原生、Skill、MCP 的行为一致。代价是校验器要自己维护。
  - **自己写校验器，不用库。** 常见的校验库（比如 valijson）需要一个适配器才能读 Glaze 的 JSON 值，适配器同样要写代码；而且这一章想讲清楚校验在做什么。代价是只覆盖子集；用“不认识的关键字不检查，但会警告”把这个边界说清楚。
  - **不认识的关键字放行，不拒绝。** 拒绝会让一个带 `anyOf` 的 MCP 工具完全不能用；放行的风险是模型传了不合格的参数，那时工具自己的检查是最后一道。
  - **类型化和手写 Schema 两种写法都留着。** 类型化适合 C++ 里写的工具（说明、范围、读取一处写完）；手写的给没有结构体的来源，也给要保持整数精确的 `add`。
  - **错误是结果，不是异常。** 模型能读到它，才能改正；异常只会终止回合。取消是例外，要让它传到循环。
  - **危险的工具默认拒绝，不做确认。** 确认要问人，是支线 llm-1.1 的事；这一章有一条能测试的规则，比留着一个没人读的字段更好。
  - **期限放在运行时，不放在每个工具里。** 工具可以自己指定（`sleep` 的 65 秒），没有就用默认。
  - **被否决：** 工具函数自己用 `try` 和 `catch` 处理一切（重复，而且忘了就崩）；用 `std::future` 加线程实现超时（协程里可以直接取消，不需要多一个线程）；把校验放进 `glz::read`（它不检查范围，而且 Skill 和 MCP 没有结构体）。
- 这一章用到的库版本：Glaze 9.1.0，Boost 1.92.0，GoogleTest 1.18.0。

## 8. 常见问题与坑

- **`||` 的一个操作数在第一次挂起之前就抛异常。** 工具函数 `throw` 之后，`call || timer` 要等定时器走完才返回，错误信息还变成了“超时”。解决办法是把调用放进一个自己捕获异常的协程（`Guarded`），再把它和定时器放进 `||`。这是这一章实测才发现的。
- **协程的参数是引用时，对象要活到协程结束。** 测试里把一个临时的 `ToolCallBlock` 传给 `Run` 再交给 `co_spawn`，临时对象在语句结束时就没了，协程拿到的是一个空的调用，工具名是空字符串。要先把它放进一个变量，活到 `io.run()` 之后。（和 1.1 里 `Ask` 的参数是同一类问题。）
- **`const auto& x = Make().member` 会悬空。** 测试里 `const Json& actual = DefinitionOf(tools.Definitions(), "sleep").parameters;` 引用了一个已经销毁的临时 vector 的元素，读出来全是 `DD`。先把 `Definitions()` 存进一个变量。
- **Glaze 写的 Schema 不能原样给模型。** 数字字段是 `$ref`，`$defs` 里是整个类型范围，根上有 `title`。要先过 `schema::Normalize`。另外 `write_json_schema` 要传 `error_on_missing_keys = true`，Schema 里才有 `required`。
- **Glaze 读结构体不检查范围。** 范围由校验器管；如果绕过运行时直接读，`ms = 70000` 会被收下。
- **`sleep` 的期限要比它能睡的时间长。** 默认期限是 30 秒，而 `sleep` 能睡 60 秒，所以它自己带 65 秒。不然一个合法的 `sleep(45000)` 会被运行时当成超时。
- **工具越多，每个请求越贵。** 四个工具的定义让第一个请求就有 1300 多个输入 token。
- **控制台会把工具的整个结果打出来。** 命令行钩子打印的是工具返回的全文（截断之后的 16 KB 也是一整行）；在终端里看会很长。需要的话，写一个只打印开头的钩子。
- **名字重复是登记时的错误。** 两个来源有同名的工具，`AddSource` 抛 `std::invalid_argument`；来源在登记之后又改名成重名的，`Definitions` 里排在后面的那个不提供，并记一条警告。
- **没检查的关键字。** 日志里出现 `uses keywords that are not checked`，说明这个工具的 Schema 用了校验器不认的关键字；工具要自己检查那一部分。
