## 2. 背景与概念

待写。（要点：四个部分按“稳定的在前、变化的在后”排序，提示缓存才能命中：①系统提示词（身份与规则、Skill 目录（1.5）、工具定义（1.4，单一来源）、Provider 的能力声明（1.2））；②历史对话（定义一个 `History` 接口，本章先用内存实现，1.9 换成 SQLite 实现；每一轮按 `channel_id` 重新生成，工具调用与结果成对保留，先做最简单的按预算裁剪，深入的压缩见支线 llm-1.6）；③当前状态（先只放会话设置、可用资源、是否有任务在进行，格式固定；做成一个单独的块，放在历史之后、最新用户消息之前，状态变了也不影响历史的缓存；留一个扩展点，以后加内容，比如阶段 2 的节点图句柄）；④最新用户信息（发言者、文本、附件引用；任务进行中收到的新消息（steering）也按顺序放在这里并标明）；组装是纯函数 `BuildContext(inputs) -> Context`，输出与协议无关，由 Provider 转成各自的格式；时间、随机数这类会变的东西不进前缀；估算每一部分的 token，超预算时先裁历史，保留系统提示词和最新信息；`--show-context` 打印组装结果和各部分的占比，用于调试；用户文本、图片说明、工具结果当作数据，与指令分开标记（深入见支线 llm-1.9）；为长期记忆、检索结果预留插槽（支线 llm-2.x）；测试：黄金文件对比，加一个“同样输入逐字节相同”的确定性测试；推理块属于历史的一部分，组装时按 Provider 的要求原样放回；历史、最新消息、工具结果都是内容块（见 1.2），组装按块处理，不拼字符串。）
