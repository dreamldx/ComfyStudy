# 1.5 Skill 机制：按需加载的能力

- 状态：已打 tag ｜ 类型：主线 ｜ tag：`chapter-1.5-skills` ｜ 上一 tag：`chapter-1.4-tool-runtime`
- 所属阶段：[阶段 1：LLM 与对话通道](README.md)
- 一句话目标：在 1.3 的循环和 1.4 的工具运行时上实现 Skill：模型一开始只看到每个 Skill 的名字和任务，用 `load_skill` 加载才得到用法和它带的工具，`unload_skill` 拿走；加载是真的登记进运行时，共享的工具按工具名引用计数；失败的回合连 Skill 一起退回，`/reset` 卸载全部；用三个玩具 Skill 演示并量化它省下的 token

## 1. 本章目标与成果

1.4 的运行时把所有工具一股脑交给模型：每个请求都带着全部工具的定义。工具一多，这既贵，也让模型更容易选错。这一章让工具按需出现：模型一开始只看到“有哪些 Skill、各自做什么事”，需要时加载一个，才得到它的用法和它带的工具。做完后你会得到：

- **Skill 的文件格式（最小版）：** `skills/<名字>/SKILL.md`。开头是用 `---` 包起来的头部，写 `name`、`description`（这个 Skill 做什么事）和 `tools`（它带哪些工具）；头部之后是正文，加载时原样交给模型。
- **`load_skill` 和 `unload_skill`：** 两个始终可用的工具。加载把 Skill 声明的工具登记进运行时，卸载把它们拿走。循环不用改：它每个 Step 本来就重新问一次工具定义（1.3 就是这样设计的）。
- **目录只写任务，不写工具名：** `load_skill` 的说明里列出每个 Skill 的名字和一句话任务；工具名要等加载之后才出现。
- **共享工具用引用计数：** 两个 Skill 可以声明同一个工具；按工具名计数，第一个 Skill 加载时登记，最后一个卸载时才拿走。
- **失败的回合连 Skill 一起忘掉：** 循环会把失败、超时、取消的回合从对话里退回去；已加载的 Skill 也退回回合开始前的样子，否则模型不记得自己要过这些工具，工具却还开着。`/reset` 则卸载全部。
- **坏 Skill 不拖垮别的：** 一个 Skill 的文件有错，就跳过它并警告，其余照常可用。
- 三个玩具 Skill（`calculator`、`timer`、`playground`）；新设置 `skills_dir`（默认 `skills`）。41 个新测试，现在一共 299 个。

## 2. 背景与概念

**为什么按需加载。** 每个请求都要带上当前所有工具的定义（名字、说明、参数的 Schema）。工具少的时候无所谓；到了后面，图像的节点有几十上百个，全放进去，每个请求都要为它们付钱，模型在一大堆工具里也更容易选错。Skill 的做法是把工具按任务分组：模型先看到一份简短的目录，需要哪类事再加载哪组。

**一个 Skill 是什么。** 一个目录，里面一个 `SKILL.md`。头部三个键：`name`（必须和目录名相同，只许小写字母、数字和连字符，最多 40 个字符）、`description`（这个 Skill 做什么事，最多 200 个字符，模型靠它决定要不要加载）、`tools`（它带哪些工具，用逗号分隔，至少一个）。头部之后是正文：怎么用这些工具，加载时原样交给模型。头部是 YAML 的一小部分（每行一个 `键: 值`），不引入 YAML 库；完整的格式留给支线 llm-4.1。

**目录里不写工具名。** 模型选的是“我要做哪类事”，不是“我要哪个函数”。目录只有名字和任务，不会随着工具变多而变长；工具名在加载之后才出现，一处是 `load_skill` 的返回值（“现在可用的工具：add”），一处是下一个 Step 的工具列表。目录写在 `load_skill` 的说明里，因为运行时每个 Step 都重新问一次说明，已加载的 Skill 后面可以标上“（loaded）”。

**加载是真的登记。** 工具的实现放在一个 `NativeTools`（“实现库”）里，但这个库本身不登记进运行时，模型看不到它。加载一个 Skill 时，对它声明的每个工具，从实现库里取出这一个工具做成一个来源（`Subset`），登记进运行时（`AddSource`）；卸载时 `RemoveSource`。这样检查参数、期限、截断、危险工具的拒绝，都还是 1.4 运行时在做，Skill 不需要自己再做一遍：加载 `playground` 之后，`shutdown` 照样被拒绝。

**共享工具：引用计数。** 同一个工具可以出现在两个 Skill 里（比如两个 Skill 都要用“读文件”）。运行时不允许两个来源有同名工具，所以按工具名数：计数从 0 变 1 时登记，从 1 变 0 时拿走。先加载 A 再加载 B，卸载 A 的时候共享的工具还在，卸载 B 才没有。顺序无关紧要。

**加载是整体的。** 一个 Skill 要么整个加载成功，要么什么也没变。如果它的某个工具名已经被运行时里别的来源占用了，`AddSource` 会抛异常；这时要把这个 Skill 之前已经登记的工具都收回，再把失败当作结果交给模型（和 1.4 一样，错误是结果，不是异常）。

**回合失败时的退回。** 循环在回合失败、超时、取消时，会把对话退回到用户消息之前。如果这时 Skill 还开着，模型的对话里没有“我加载过它”的记录，工具列表里却多了工具，两边对不上。`SkillTools` 同时是一个钩子（`AgentHook`）：回合开始时记下已加载的集合，回合不是以回答结束就恢复它。`/reset` 也一样，让运行时对每个来源调用 `StartOver()`，`SkillTools` 把全部 Skill 卸载。恢复函数不抛异常：它是被钩子和聊天命令调用的，不能让它把别的东西带倒。

**这一章不做的。** Skill 的完整格式、权限、热重载（支线 llm-04）；先只给名字和任务、需要时再读正文和资源的渐进式披露（llm-4.2）；Skill 自带资源和脚本（llm-4.4）；真正的图像节点 Skill（阶段 2 以后）。

```cpp
  static constexpr const char* kLoad = "load_skill";
  static constexpr const char* kUnload = "unload_skill";

  // `runtime` is the one this source is added to; it has to be there for as long as this one is. Throws
  // std::invalid_argument when a Skill names a tool that `library` does not have.
  SkillTools(SkillCatalog catalog, std::shared_ptr<NativeTools> library, ToolRuntime& runtime);

  const std::vector<std::string>& Loaded() const { return loaded_; }

  boost::asio::awaitable<ToolResult> Call(const std::string& name, const json::Value& arguments) override;

  boost::asio::awaitable<void> OnTurnStarted(const TurnStarted&) override;
  boost::asio::awaitable<void> OnTurnFinished(const TurnFinished& finished) override;
```

```cpp
std::vector<ToolSpec> SkillTools::Specs() const {
  std::string list;
  json::Value names = json::Array();
  for (const SkillInfo& skill : catalog_.skills) {
    list += "\n- " + skill.name + ": " + skill.description + (IsLoaded(skill.name) ? " (loaded)" : "");
    json::Push(names, skill.name);
  }
  const auto name_schema = [&](const char* what) {
    return json::Value{{"type", "object"},
                       {"properties", {{"name", {{"type", "string"}, {"description", what}, {"enum", names}}}}},
                       {"required", json::Array({"name"})},
                       {"additionalProperties", false}};
  };

  ToolSpec load;
  load.name = kLoad;
  load.description =
      "Loads a Skill: you get its instructions, and the tools it brings can be used from the next step on. Load a Skill when the "
      "task needs it. The Skills:" + list;
  load.parameters = name_schema("the Skill to load");
  load.effect = Effect::kSideEffect;

  ToolSpec unload;
  unload.name = kUnload;
  unload.description = "Unloads a Skill that was loaded: the tools it brought are taken away (unless another loaded Skill brings them too).";
  unload.parameters = name_schema("the Skill to unload");
  unload.effect = Effect::kSideEffect;
  return {load, unload};
}
```

**登记：计数 0 到 1 才登记。** 对 Skill 声明的每个工具，计数为 0 时从实现库取出这一个工具做成来源，登记进运行时。如果登记失败（别的来源已经有同名工具），`catch` 把这个 Skill 已经登记的工具收回，再把异常抛出去，保证“整个加载或什么都没变”。

<!-- src: src/skill_tools.cpp#L42-L68 -->
```cpp
void SkillTools::Attach(const SkillInfo& skill) {
  std::vector<std::string> added;
  try {
    for (const std::string& tool : skill.tools) {
      Count& count = counts_[tool];
      if (count.skills == 0) {
        auto source = library_->Subset({tool});
        runtime_.AddSource(source);  // throws when another source has a tool of this name
        count.source = std::move(source);
      }
      ++count.skills;
      added.push_back(tool);
    }
  } catch (...) {
    // take back what this Skill had added so far, so that a Skill is loaded whole or not at all
    for (const std::string& tool : added) {
      Count& count = counts_[tool];
      if (--count.skills == 0) {
        runtime_.RemoveSource(count.source);
        counts_.erase(tool);
      }
    }
    const auto failed = counts_.find(skill.tools[added.size()]);
    if (failed != counts_.end() && failed->second.skills == 0) counts_.erase(failed);
    throw;
  }
}
```

**卸载：计数回到 0 才拿走。** 返回真正被拿走的工具，用来告诉模型“拿走了哪些”。共享的工具计数没到 0，就不在这个列表里。

<!-- src: src/skill_tools.cpp#L70-L82 -->
```cpp
std::vector<std::string> SkillTools::Detach(const SkillInfo& skill) {
  std::vector<std::string> removed;
  for (const std::string& tool : skill.tools) {
    const auto found = counts_.find(tool);
    if (found == counts_.end()) continue;
    if (--found->second.skills == 0) {
      runtime_.RemoveSource(found->second.source);
      counts_.erase(found);
      removed.push_back(tool);
    }
  }
  return removed;
}
```

```cpp
boost::asio::awaitable<ToolResult> SkillTools::Call(const std::string& name, const json::Value& arguments) {
  const std::string skill_name = json::StringOr(arguments, "name", "");
  const SkillInfo* skill = FindSkill(skill_name);
  if (skill == nullptr) {
    std::vector<std::string> names;
    for (const SkillInfo& known : catalog_.skills) names.push_back(known.name);
    co_return Failure("there is no Skill called \"" + skill_name + "\"; the Skills are: " + Joined(names));
  }

  if (name == kLoad) {
    if (IsLoaded(skill_name)) co_return Failure("the Skill \"" + skill_name + "\" is already loaded");
    try {
      Attach(*skill);
    } catch (const std::exception& e) {
      co_return Failure("the Skill \"" + skill_name + "\" could not be loaded: " + e.what());
    }
    loaded_.push_back(skill_name);
    std::string text = "The Skill \"" + skill_name + "\" is loaded. Tools you can use now: " + Joined(skill->tools) + ".";
    if (!skill->body.empty()) text += "\n\n" + skill->body;
    co_return ToolResult{text, false};
  }

  if (name == kUnload) {
    if (!IsLoaded(skill_name)) co_return Failure("the Skill \"" + skill_name + "\" is not loaded");
    const std::vector<std::string> removed = Detach(*skill);
    loaded_.erase(std::find(loaded_.begin(), loaded_.end(), skill_name));
    std::string text = "The Skill \"" + skill_name + "\" is unloaded.";
    if (!removed.empty()) text += " Tools taken away: " + Joined(removed) + ".";
    co_return ToolResult{text, false};
  }

  co_return Failure("there is no tool called \"" + name + "\"");
}
```

**退回。** 先按“最后加载的先卸”的顺序卸掉不在目标里的，再把目标里还没加载的加载上；加载不上的（比如工具名已经被别的来源占用）跳过。整个函数不抛异常。

<!-- src: src/skill_tools.cpp#L84-L106 -->
```cpp
void SkillTools::Restore(const std::vector<std::string>& wanted) {
  try {
    const std::vector<std::string> now = loaded_;
    for (auto it = now.rbegin(); it != now.rend(); ++it) {  // the last loaded goes first
      if (std::find(wanted.begin(), wanted.end(), *it) != wanted.end()) continue;
      if (const SkillInfo* skill = FindSkill(*it)) Detach(*skill);
      loaded_.erase(std::find(loaded_.begin(), loaded_.end(), *it));
    }
    for (const std::string& name : wanted) {
      if (IsLoaded(name)) continue;
      const SkillInfo* skill = FindSkill(name);
      if (skill == nullptr) continue;
      try {
        Attach(*skill);
        loaded_.push_back(name);
      } catch (const std::exception&) {
        // not loadable now (another source has taken a tool name since): left out
      }
    }
  } catch (...) {
    // Restore is called by a hook and by /reset and must not throw
  }
}
```

**运行时的两处新东西。** `RemoveSource` 只是把来源从列表里去掉；正在执行的调用（比如 `unload_skill` 自己）手里已经有这个来源的 `shared_ptr`，所以工具可以在调用里拿走自己的来源，这有测试。`StartOver` 先复制一份来源列表再逐个调用，因为某个来源的 `StartOver` 可能增减来源。

<!-- src: src/tool_runtime.cpp#L126-L136 -->
```cpp
bool ToolRuntime::RemoveSource(const std::shared_ptr<ToolSource>& source) {
  const auto found = std::find(sources_.begin(), sources_.end(), source);
  if (found == sources_.end()) return false;
  sources_.erase(found);
  return true;
}

void ToolRuntime::StartOver() {
  const std::vector<std::shared_ptr<ToolSource>> sources = sources_;  // a source may add or remove sources
  for (const std::shared_ptr<ToolSource>& source : sources) source->StartOver();
}
```

```cpp
        const auto found = values.find("skills_dir");
        const std::filesystem::path directory = found == values.end() || found->second.empty() ? "skills" : found->second;
        const agent::SkillCatalog catalog =
            agent::LoadSkills(directory, std::set<std::string>(names.begin(), names.end()),
                              {agent::SkillTools::kLoad, agent::SkillTools::kUnload});
        for (const std::string& problem : catalog.problems) spdlog::warn("Skill {}", problem);
        if (catalog.skills.empty()) throw std::runtime_error("there is no usable Skill in \"" + directory.string() + "\"");
        skills = std::make_shared<agent::SkillTools>(catalog, library, tools);
        tools.AddSource(skills);
      }
      agent::Hooks extra_hooks;
      if (skills) extra_hooks.push_back(skills);
```

## 7. 技术资料

- Boost.Asio 1.92.0 和 Glaze 9.1.0 与 1.4 一样；这一章没有新增依赖。
- Anthropic 的 Agent Skills 约定：一个 Skill 是一个目录，里面的 `SKILL.md` 有 YAML 头部（名字、说明）和正文，说明给模型看，用来决定要不要读正文。这一章的格式同一个形状，但头部多了 `tools`；对照和完善是支线 llm-4.1 的事。
- 设计取舍：
  - **目录放在 `load_skill` 的说明里。** 运行时每个 Step 都重新问说明，所以“（loaded）”这样的标记能实时更新；不碰系统提示词（那是 1.6 的事）。代价：目录随着 Skill 增多而变长，每个请求都带，支线 llm-4.2 去优化。被否决：写进系统提示词（和 1.6 的组装冲突）；多一个 `list_skills` 工具（多一个来回，多一个工具）。
  - **Skill 里写工具清单，不让工具自己声明属于哪个 Skill。** 清单在 Skill 里，和支线 llm-4.5“Skill 声明要用的工具、装载时只开放声明过的”同一个形状。清单和工具定义是两份信息，会不会漂移？启动时检查：声明了不存在的工具，这个 Skill 被跳过并警告，所以漂移变成启动时就能看到的错误。
  - **真的登记和注销，不做可见性过滤。** 好处是以后 Skill 的工具来自要在加载时才启动的东西（比如一个 MCP 服务）时，机制不用改。代价是运行时要有 `RemoveSource`，要处理共享工具的计数。
  - **共享工具用引用计数，按工具名数。** 每个被登记的工具各是一个只含它的来源，计数 0 到 1 登记、1 到 0 拿走。被否决：一个工具只能属于一个 Skill（简单，但共享是很自然的需求）。
  - **加载状态放在 `SkillTools` 里，用钩子退回。** 被否决：从对话历史里推出加载状态（回滚和重启都自动正确，但 `ToolSet` 拿不到对话，要改接口和循环；1.9 做持久化时再看）；全局一份（多个会话会互相影响）。
  - **坏 Skill 跳过并警告。** 一个文件写错不应让整个目录不可用；但一个能用的都没有时是启动错误，因为那时 `--tools` 没有意义。

## 8. 常见问题与坑

- **`runtime.AddSource` 会抛异常。** 工具名被别的来源占用时它抛 `std::invalid_argument`。加载一个 Skill 时要把已登记的收回再抛，否则留下半个 Skill。测试 `ASkillWhoseToolNameIsTakenByAnotherSourceIsNotLoadedAndLeavesNothingBehind` 管着它。
- **退回只在回合不是 `kDone` 时做。** 回合以回答结束，模型的对话里有加载的记录，工具开着是对的；失败、取消、超时、步数用完、没有文字，对话被退回，Skill 也要退回。
- **恢复函数不能抛异常。** 它被钩子调用（钩子抛异常会被记录并忽略，但本该做的恢复就没做了）和被 `/reset` 调用。里面的加载可能失败（别的来源占了名字），失败就跳过这个 Skill。
- **目录写得含糊，模型就选不对。** 上面“shutdown”的例子。一句话的任务要让模型能分辨，哪个 Skill 里有它要的能力。
- **Skill 多了一个 Step。** 每个要用工具的回合，都要先加载。工具少的时候这是净亏损（见上面的 token 对比）。
- **工具集变化会让提示缓存失效。** 工具定义是请求前缀的一部分；对话中途加载或卸载，前缀变了，缓存就不能用。
- **`skills_dir` 的相对路径从运行目录算。** 不是从可执行文件所在的目录；从别的目录运行会找不到。
- **测试里的 UTF-8 要写成转义。** 说明长度按字符数的测试用 `"\u4f60"` 而不是直接写汉字，免得源文件的编码问题让测试悄悄变成别的意思。

## 9. 练习

练习：

1. 写一个新的 Skill `echo`，带 `repeat` 一个工具；启动程序，看目录里多了它。再让它的 `tools:` 写一个不存在的名字，看启动时的警告。
2. 让两个 Skill 都声明 `repeat`，加载一个，再加载另一个，卸载其中一个，用 `--tools` 让模型调用 `repeat`，看它是不是一直在。
3. 把 `description` 写得很含糊（比如“一些东西”），看模型还能不能选对 Skill；再改成具体的，比较。
4. 在 `load_skill` 返回的文字里不带正文，只说“已加载”，看模型怎么用工具。正文起了什么作用？
5. 加一个设置，让 `SkillTools` 在启动时就加载某个 Skill（比如常用的那个）。想一想：这和“按需”有什么冲突？
6. 现在加载状态放在 `SkillTools` 里，退回靠钩子。想一想：从对话历史里推出已加载的 Skill（扫描历史里的 `load_skill` 和 `unload_skill` 调用）要改哪些接口？这样做的好处是什么？
7. 想一想：为什么 `Restore` 先卸后加，而且卸载按“最后加载的先卸”？
8. 把 `Attach` 里 `catch` 收回已登记工具的那段去掉，看哪个测试失败，再用调试器看加载失败之后运行时里留了什么。
